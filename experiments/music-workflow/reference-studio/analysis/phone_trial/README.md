# 手机录音：指定主旋律的声音分离试验

输入：`D:/Sound/temp/music/手机录音-20261023-233819.wav`。
用户指定目标：**45～53 秒，主导旋律的音色**。

本次只准备真实模型的声音候选与试听对照，不改主工作站、原录音或此前案例。
模型输出的名称不是用户确认的乐器名称；生成了文件不代表已经提取成功。

## 输入与时间

- 原文件：48 kHz、双声道、float32，183.99625 秒。
- SHA-256：`5dc9759718578315815c8119b3cb4e54e26f60c0401a6e3fa69f912a84ae8f58`。
- 给模型的上下文：44～54 秒，10 秒；交付试听裁到45～53秒，8秒。
- `cases/phone-recording-20261023-233819/source-manifest.json` 保留来源和逐样本裁剪核验。

## 方法与文件

- `baseline.py`：已缓存的官方 Hybrid Demucs 四类估计，仅作普通分轨基线。
- `../mus3d_trial/`：官方 MuS3D 的 SEG 声源发现与查询式 BS-Locoformer，
  使用本机 CPU 和独立缓存。来源、运行适配、参数及资源摘要另有记录。
- `prepare_comparison.py`：把模型的10秒输出重采样到48kHz，裁出指定8秒；
  保留浮点估计，并生成24位WAV试听。

每个候选有独立试听、`原片段减去该候选` 的剩余声，以及一个24.5秒对照文件：

1. 原片段8秒。
2. 静音0.25秒。
3. 候选8秒。
4. 静音0.25秒。
5. 剩余声8秒。

候选未分别归一化。若峰值要求衰减，同一个对照中的三段采用同一增益并在清单记录。
剩余声只是减法结果，不能宣称是干净伴奏；独立查询的候选也不保证互斥，不能任意相加
后当成正确的完整分轨。没有合成替换、自动编曲或推测原作者插件参数。

## 核验范围

数值核验检查时间对齐、长度、采样率、声道、量化误差、异常值、削波和原文件摘要。
它不能代替用户判断主旋律是否正确、音色细节是否保留、伴奏串音是否可接受。
本机推理期间禁用网络连接；没有上传录音、打开真实音频设备或操控桌面。

运行结果保存在此独立案例的 `hdemucs/`、`mus3d/`、`audition/` 目录。
新模型环境与权重位于项目 `.cache/mus3d-experiment/`，不修改全局Python环境。
