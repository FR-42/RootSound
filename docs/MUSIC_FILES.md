# 音乐文件的打开与保存

## 一条打开路径

乐曲库继续按 `project` 的实际目录逐层浏览，保留图标、文件名和分页。点文件直接
打开；顶栏的“打开”可以选择其他目录的文件。不再在打开 MIDI 后自动创建工程。

| 文件 | 打开后如何编辑 | “保存” / Ctrl+S |
| --- | --- | --- |
| `.rootsound` | 简乐完整工程 | 写回原工程 |
| `.mid`、`.midi`、`.smf`、`.kar` | MIDI 音符、GM 乐器、力度、起始位置、时值和速度段 | 写回 MIDI |
| `.rmi` | RIFF 包装的 MIDI | 保持 RIFF MIDI 包装 |
| `.musicxml`、`.xml` | MusicXML 五线谱转换成可编辑音符 | 写回 MusicXML |
| `.mxl` | 压缩 MusicXML | 写回压缩 MusicXML |
| `.rsproject` | 旧版便携简乐工程 | 写回旧版工程包 |

普通 XML 必须确实是 MusicXML；不把任意 XML、音频文件或其他 DAW 的私有工程
当成可编辑乐谱。旧 `project.json` 文件夹工程仍走已有兼容入口。

## 保存规则

打开时读取源文件，编辑保存在内存草稿里。按 Ctrl／⌘+Shift+S 可另存为完整
的 .rootsound 工程。原格式的普通保存留在原目录，
改名后保留原扩展名；另存的新工程进入默认乐曲库，原文件不变。

没有音乐修改时，外部格式保存保留原始字节。普通 MIDI 音符／速度编辑尽量沿用
原轨道，保留控制器、踏板、弯音、歌词、文本和系统事件。当前采样应用延音和保持音踏板，音符保持实际松键位置。弯音、连续控制与触后数据保存在工程中，供 MIDI 写回使用。

更换乐器或独立修改逐音音量／声像可能需要重建 MIDI 通道；标准演奏事件会复制到
对应的新通道，无法保留的设备设置会在保存前说明。重建路径最多使用 15 个旋律通道和一个鼓通道；超出时请另存完整
工程。每拍细分、隐藏／未定义音符、自定义采样和包络等不属于通用 MIDI 能力，
不能完整写回时同样先提示。绝不把简乐 JSON 伪装成 MIDI。

MusicXML 支持 partwise／timewise、复音、和弦、休止、连音、移调、GM 乐器与速度；
反复目前按谱面顺序演奏一遍，部分装饰音和演奏法未展开。编辑后写回会生成常规
小节、跨小节连音及演奏数据；排版、歌词、原声部布局等不保证保留，保存前需确认。
需要保留原谱时取消写回，另存为 `.rootsound`。

MIDI 仍以 PPQ 的 SMF 0／1 型为支持范围，不支持独立歌曲序列的 2 型和 SMPTE
时间分度。桌面外部文件入口上限 32 MiB，MIDI 解析上限仍为 10 MiB／50000 音符；
编辑器限制仍适用，包括 1024 拍、128 个音符组；速度扩展至 1～1000 BPM，音高为
完整 MIDI 0～127（C−1～G9，约 8.1758～12543.854 Hz）。调速输入、敲击定速、
音符编辑和试听统一使用这一范围。超出采样原始键区的音高，用邻近录音移调播放。
速度段上限提高到 2048，正常变速不再拆散成旧式片段。

MIDI 的速度数值为 24 位微秒／四分音符，最低约能表示 3.58 BPM；设置得更慢时，
原格式保存会说明原因并拒绝截断数值，可另存 `.rootsound`。原生工程和 MusicXML
可以保留 1 BPM。界面以四舍五入后的整数显示 BPM，导入时保留精确速度。
MIDI 导入的每个实际变速点对应一个 BPM 卷帘，音符继续按原始
拍位置和时值放置；旧导入工程尚有变速记录时，也会据此恢复多卷帘坐标。

保存先生成并验证内容，再原子替换；源文件被外部程序改动时拒绝覆盖。编辑草稿和
上次保存的基线单独保留在当前会话中，刷新渲染界面不会把草稿误当成已保存版本。
没有新增 `.bak` 或旁置音乐文件。

## 网页版

支持同样的音乐格式入口，沿用网页版的 16 MiB、64 拍、2048 音符和有限音色范围。
打开外部格式后，“下载原格式”生成相应扩展名的文件；浏览器下载不会自动覆盖本机
原文件。按 Ctrl／⌘+Shift+S 可下载完整 .rootsound 工程。网页的本地构建不等于 GitHub Pages 已更新。

## 实现与检查

音乐转换在应用层，原生宿主只负责文件选择、会话、并发检查与原子写入。解析代码
按需加载，不给普通欢迎页和原生工程启动添加完整格式解析器。新增依赖为 MIT 的
`midi-file`、`@xmldom/xmldom` 和 `fflate`；许可随界面资源放在
`public/licenses/music-file-LICENSES.txt`。

`npm run test:music-files` 运行小型格式往返与入口检查；
`node scripts/test-music-files.mjs` 使用临时目录检查实际文件服务；
`node scripts/test-music-files-ui.mjs` 使用隐藏编辑器检查实际保存流程。后两项需要
对应的宿主与界面构建，全程不修改用户歌曲、不操控用户桌面、不使用物理声卡。

格式依据为 [W3C MusicXML 4.0](https://www.w3.org/2021/06/musicxml40/)。
`python scripts/test-musicxml-schema.py` 用官方规范仓库的 XSD 校验生成的小型乐谱，
只在测试目录缓存规范文件，需要预装 lxml；不是应用运行依赖。
