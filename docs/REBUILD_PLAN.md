## 1. 新组织方式下的第一条真实创作流程

音频执行归属已确认：采用后台平行的声音运行模块，统一实际发声与音频渲染。模块公开能力、内容引用、编辑稿以及本阶段的时间/音高表示已形成可运行的第一版，技术选择保持可替换，不因此冻结整个工作站的未来模型。

这些边界记录在[第一阶段基础设计](REBUILD_FOUNDATION.md)。声音运行的模块地位与主要分工已经批准；继续将第一条流程必要的数据与交流约定落实成可验证实现，不把其余建议默认为已获批准。

进度：声音制作、乐句谱写和歌曲编排已作为独立模块与工作区协作，公共库保管内容、编辑稿及持久历史。歌曲引用已保存乐句，乐句引用已保存声音，采样音色再引用完整原件；同歌复制保留引用，普通修改保存时分离必要层级，跨歌采用则建立独立完整依赖。五批基础流程已由用户验收，后续各轮验证分别保留。采样获取可保存、重新打开和试听；独立旋律识别把单人哼唱整理成基础合成乐句，采样音色让原声音本身成为乐器；细调、共创、歌曲和工程继续沿公开能力协作。桌面与存储实现可替换；AI 与安装包尚未实现。

目标流程：

1. 创建一件能试听的音色，交给公共素材与工程管理保存。
2. 乐句谱写取得这件音色，生成并可修改一段简短乐句。
3. 歌曲编排引用乐句，至少能重复摆放和改变起始位置。
4. 各部分按共同规范协作，保存、关闭、重新打开后继续编辑与试听。

当前实现覆盖上述四步所需的基本能力，包括歌曲时间线、多轨摆放、复制重复、混音控制和保存恢复。用户已确定歌曲默认各乐句保留原速，歌曲也可明确选择全部跟随歌曲速度；此规则不改写源乐句。此前桌面联动、退出恢复与 WAV 文件有实际验证记录，后续共创、采样及本轮识别只以源码、自动化和构建为依据，原生检查按实际运行轮次分别记录，不增加桌面控制；不加入 AI 或独立乐句交换文件，也不以基础流程通过代替整个工作站的品质评价。

验证要点：

- 模块能自由交流，无需每次经过最高指挥中心批准或转发。
- 音色、演奏内容和歌曲摆放位置分别存在；复制乐句不隐含复制整套音色。
- 公共管理保存内容，执行单位实现音乐行为，界面不直接改兄弟模块内部数据。
- 单个声音能独立试听，不要求建立歌曲。
- 显示和播放响应明确；未实现的部分清楚标注，不用空按钮或假生成冒充功能。

这是一项架构与内容协作验证，尚不代表“零摩擦创作”已经达成。

## 2. 编辑、安全保存与完整导出

- 在同曲乐句反复出现、多个乐句共用音色的场景中，验证普通修改只影响当前使用路径，不要求用户先手工制作副本；不同歌曲素材身份必须独立。
- 联合应用列出直接、间接的具体使用位置，只更新选中位置；同曲复制仍共享引用，未选位置保留原内容；跨歌曲采用独立结果。
- 嵌套联合先暂存在父乐句，父级保存才应用外部位置；取消父级不影响外部，冲突或失败不留下半套修改。
- 原子提交与复合撤销覆盖引用调整；后续已保存作品仍需的依赖保留，外部目标变化时拒绝旧历史覆盖，不提前实现多人实时协作。
- 输出可播放的普通音频；基础导出先复用声音运行的公开离线能力，不为尚未实现的后期效果创建空模块。
- 已落实当前音乐模型的工程首版，打包所有间接依赖与读取所需信息；后续按采样、插件等实际能力演进格式，不把临时 JSON 容器冻结为最终规范。
- 在空素材库、断网的兼容 RootSound 环境中重开，能够继续编辑和输出；改变原库不改变已导出的文件。
- 验证目标库里存在同名或相同标识内容时，不发生静默覆盖。

当前已实现按实际使用路径分离所需的音色和乐句，普通保存仅当前处，联合应用可选择具体位置；零或单引用覆盖，多引用为当前位置新建，多引用且没有指定位置的直接库编辑另存。同曲复制保留下层引用；跨歌引入和另存新歌曲自动隔离全部依赖，不向普通用户增加复制策略选择。旧库加载不批量改写，相关编辑迁移，旧历史可恢复旧状态。既有 27 项引用测试覆盖重复位置、间接路径、嵌套暂存与取消、外部冲突、失败保留和复合撤销；后续范围与整链路回归按实际轮次另记。

乐句和歌曲每稿最多 64 步撤销重做随编辑稿原子保存、跨重启恢复；引用更新作为复合操作一起撤销、重做，联合应用按当次范围整体恢复，涉及的外部目标后来被修改则拒绝操作。当前歌曲后来另行保存的版本及其必要派生依赖受到保护。旧库从更新后的编辑积累历史，音色制作已有独立参数撤销入口。基础普通音频导出已实现，试听和离线生成共用发声图，输出 WAV，具有进度、取消和可靠文件保存。

`.rsproject` 已携带当前歌曲稿、显式工程成员及其递归依赖，可在兼容 RootSound 空库中离线继续编辑。导出捕获快照但不改源库；当前清单中尚未完成的乐句或音色稿须先完成或取消。导入验证未知版本、缺失或循环依赖、错误类型后，一次创建新身份、成员关系和根稿，同名作品与原稿保留，取消和失败不留半套内容。歌曲主“保存工程…”与 Ctrl+S 统一打开位置选择，空歌曲也可保存；欢迎页和歌曲工具栏可打开工程。本机编辑稿自动保留供恢复，不代替用户主动文件保存。

没有附加成员继续使用 JSON v1，有成员使用含 `memberIds` 的 v2；当前可读取两版。所有记录必须恰好属于歌曲和成员的联合闭包，不携带其他歌曲、旧保存、撤销历史、编辑上下文或应用偏好，不是整库备份。暂定上限 32 MiB、8192 份内容。原始采样按引用收齐并重映射；PCM WAV 用内置解码，其他编码仍受目标环境解码能力约束。第三方插件、AI 和任意模块操作的统一历史仍未实现。`.rssound` 用于单个无依赖电子音色，WAV 仍是播放用途，均不替代可编辑工程。

本轮验证重点：素材管理只列当前工程，相同身份的来源/工作稿只展示一次，不显示仅历史保管的对象；公共起点只在实体栏另列。明确另存的未编排副本作为本曲成员保留并随工程文件往返；主保存与快捷键行为一致，输入提交、空歌、取消、错误及未完成子编辑均有明确结果。本轮只使用源码和隔离的程序化验证，不观察屏幕、不操作桌面、不访问真实资料库或设备，结果另记。

## 4. 引导共创与 AI 能力

- 共创可采用空白、已保存乐句或本轮已确认的哼唱识别乐句作为起点；复杂参考音频、伴奏分离和复调识别仍需后续分别验证。
- 旋律底稿与强化方案分别保留，每轮少量候选可试听、选择和返回。
- 选中的方案能交给精细模块，编辑后可回当前会话继续探索。
- AI 接入方法与联网服务按需选择，明确成本、延迟、可编辑输出与离线边界。
- 已取得并保存的完整成果可离线继续编辑。生成失败或等待不打断本地创作。
- 若某算法只能输出混合音频，应如实表达可编辑范围，不称为完整结构化生成。

当前离线首版提供三个可试听方向，由明确的本地规则调整声音质感，并在允许范围内增加简单低音和铺底。候选试听不写库，选择结果与旅途历史一次保存；换起点保留原稿，跨重启可撤销重做。细调当前结果后可回到同一旅途继续探索；尚有未完成细调时，先完成或取消，不能用新候选把它盖过。“用它创作歌曲”生成新歌，不覆盖旧歌。

本轮接通采样中的单人清唱或哼唱：最长 30 秒，超长拒绝且不截断；本地后台识别得到音符与休止，先试听，确认后才原子保存合成音色、乐句和稿。采用音高以实际 Hz 保存，不推测 BPM、调性或自动纠音；默认 120 仅是秒到拍的编辑坐标，维持原演唱时间。原采样不改动、不强制保存，想跨退出保留原录音仍需单独保存采样。取消、换源和离开终止后台分析与旧试听，迟到结果不可采用。

“去细调”保存后回到同一旅途，“继续共创”直接以这段旋律起步，之后可编歌与工程交付。带采样音色的乐句也能共创；保留手工参数和原件，通过合成伴奏增加变化。当前只验证合成音频，颤音、滑音仍整理为平直音符，不保完整音高曲线；识别置信度和提示只是核对依据，不能保证真实歌手或混合歌曲鲁棒性。尚无聊天输入、AI、偏好学习、歌词识别、复调或伴奏分离，不能称为完整智能共创。下一步仍需用户检验真实哼唱、三个方向和往返是否有用，再决定更细致的输入与引导方法。此阶段与精细模块交替推进；共创是项目核心体验之一，不能无限推迟。

## 5. 扩展采样来源与在线生态

已实现独立采样获取：导入保留原文件字节，本地支持 PCM WAV 整数与浮点解码，其他编码按环境能力尝试；麦克风以实际采集时钟录制最长 30 秒的单声道浮点 WAV。试听经统一声音运行，采样保存为公共库中的独立内容，素材分类、重新打开和启动入口已接通。采集请求正常麦克风授权，取消、失败和迟到结果不覆盖原内容。

暂定原文件 16 MiB、解码后 120 秒及 64 MiB；请求关闭设备音频处理不等于保证硬件逐位无损。未保存采样仅在内存中，切换工作区保留本次已完成内容，完全退出会丢失；替换前有“保存后继续 / 放弃并继续 / 返回”，失败保留并可重试。没有为采样建立持久编辑稿，哼唱识别另行生成可编辑合成乐句，不能将这些首版等同于完整采样工作流。本轮不进行真实录音、人声或桌面验证，检查范围与最终统计见进展文档。

本轮已把原件制作成独立采样音色，范围、原音高、包络与音量非破坏性保存，可用于乐句、歌曲、WAV 和完整工程；共享原件不复制进音符或历史。单次播放、变速移调与缓存限额均为可调整首版，不等于完整采样器。371 项应用测试和最终 Windows 构建通过，实际听感与界面仍待验收。
