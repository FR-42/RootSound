# 音乐流程实验

这里是供你亲自跑通音乐制作流程的独立实验区。你描述要得到的效果，助手负责选择方案、实现和验证。实验结果不自动成为主工作站的设计决定；主工作站的代码、资料库和启动入口独立保留。

| 工具 | 日常入口 | 用途 |
| --- | --- | --- |
| 蓝牙录音 | 蓝牙录音.exe | 接收并录制手机音乐 |
| [采样编辑](sample-editor/README.md) | 采样编辑.exe | 导入音乐，观察频谱或波形，拖动蓝线截取采样 |
| [音色打磨](timbre-lab/README.md) | 音色打磨.exe | 清理采样、多段对照，校准音高和延音，做成可演奏音色 |

流程：蓝牙录音导出歌曲 WAV → 采样编辑截出短声音 → 音色打磨清理并试奏。
音色打磨支持把同一音色的多段片段一起对照；也可以只用一段。它导出的 WAV
可用于主工作站采样音色流程，`.rstimbre` 则由实验工具保管完整演奏设置。

## 第一个工具：蓝牙录音

双击本目录的 **`蓝牙录音.exe`**。它直接打开已构建的工具，不会在日常启动时下载或编译。

1. 点击 **连接**。首次使用，点击“打开蓝牙设置配对”，在 Windows 和手机上完成配对；手机看到的是电脑的蓝牙名称。配对后，工具会发现手机；有多个设备时，选中你的手机，再点连接。
2. 界面显示“已连接”后，**开始录音**才可用。单纯“已配对”不算音频已连接。手机可以像使用蓝牙音箱那样，把音乐播放到这台电脑。
3. 点击 **开始录音**，在手机播放音乐。计时与音量条会变化。也可以先播放，再选择开始录音的时刻。录制的是电脑默认播放设备的声音；录音时请暂停其他程序的声音，并避免通知提示音。
4. 点击 **结束录音**。点击 **导出为音频文件…**，在系统文件保存窗口选择位置，得到 WAV 文件。取消保存窗口不会丢掉这次录音，可以重新导出。
5. **重新开始**始终可用：停止并清空当前录音，取消正在准备的录音或尚未完成的导出，回到可以再次录音的状态。**蓝牙连接和已经导出的文件都保留**，手机可以继续播放，不用重新连接。若手机尚在连接，重置也不会取消它。

导出文件是独立的用户文件；重新开始不会打开、修改或删除它，即使它正被播放器占用。只清理本轮私有临时录音，不扫描其他文件或主工作站资料。正常关闭工具会结束蓝牙接收，保留已经导出的文件。

## 首次使用需要知道

- 需要 Windows 10 2004 或更新版本、支持经典蓝牙的适配器、可用的电脑声音输出，以及 .NET 9 桌面运行环境。本机已有开发运行环境。首次配对仍由 Windows 管理，工具不会安装驱动或修改系统蓝牙名称。
- 使用 Windows 正式的蓝牙音乐接收能力（A2DP 接收端），手机把电脑当作音频接收设备；这不是带麦克风通话功能的耳机仿真。实际可用性仍取决于手机、蓝牙硬件与驱动。
- **录制电脑默认播放设备的声音**，包括手机通过蓝牙播放的音乐，以及该设备上的其他程序、通知提示音。不打开麦克风，也不再要求 Windows 提供手机独立输入。2026-10-24 用户取消了“只录手机”的要求，以跑通流程为先。
- 手机声音仍通过电脑正常播放，工具不重复播放、不修改系统监听或声音设置。界面显示实际录制的播放设备；请让手机声音从 Windows 默认播放设备输出。录音中手机断开、默认播放设备切换或失效时，停止并保留已有片段；重新开始后可录新的默认播放设备。
- WAV 保留电脑播放输出的实际采样率、声道与 PCM/浮点格式，不再有损编码。蓝牙传输和电脑音频处理可能已改变音频，不能称为手机原始文件的无损复制。超长录音超过普通 WAV 容量时使用 RF64。
- 录音流式写磁盘，没有主工作站短采样的 30 秒限制；长度受可用磁盘空间限制。临时录音放在 `%LOCALAPPDATA%\RootSoundExperiments\BluetoothRecorder\takes\` 的本次独立目录。正常关闭或重新开始会清理本次临时文件；崩溃后的旧临时目录不自动扫描删除。

## 构建与检查

修改源代码后运行 **`构建并打开蓝牙录音.bat`**。它构建成功后才切换独立启动目标，失败会保留旧目标。日常直接点 EXE 即可。入口依赖 `bluetooth-recorder/.builds/` 配套文件，不能只复制这一枚小 EXE 到其他机器。

开发检查，不会启动界面或真实蓝牙/声音设备：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File experiments/music-workflow/Build-BluetoothRecorder.ps1 -Test
```

实现依据：[微软蓝牙音频接收说明](https://learn.microsoft.com/en-us/windows/apps/develop/media-playback/enable-remote-audio-playback)、[微软播放输出回环录音说明](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)。录音使用默认播放设备的共享 WASAPI loopback，不依赖“立体声混音”设备、手机独立录音端点或额外驱动。

当前 73 组检查及完整构建通过：录音15、接收13、会话18、连接录音7，以及保留的旧来源/身份诊断20组。覆盖连续重置重录、连接门控、取消竞态、音频包、文件格式及导出保留。旧手机专属来源代码已移到测试诊断目录，不随程序发布，也不会阻止开始录音。

本机默认播放设备已通过共享 loopback 初始化和采集接口取得检查。这项检查没有启动音频流、读取声音、改变蓝牙连接或操作桌面。真实歌曲录音和重录听感仍待使用确认。关闭旧工具后重新打开 `蓝牙录音.exe`，可先录十几秒并导出，再在保持手机播放的同时重新开始并录第二轮。

需要排查兼容性时，可单独检查默认播放设备能否初始化回环录音。报告留在本机，不启动播放或录音、不读取音频包：

```powershell
dotnet run --project experiments/music-workflow/bluetooth-recorder/tests/RootSound.BluetoothRecorder.Tests.csproj -c Release -- --probe-output-loopback .test-output/bluetooth-output-probe.json
```

此前手机身份读取错误已单独修复，但用户随后仍遇到独立输入不可用，因此改为上述播放输出录音。旧诊断命令 `--inspect-phone-sources` 仅供开发排查，不是当前录音的前置步骤。
