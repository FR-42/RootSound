3. Peak extraction preserves native branch/rounding behavior
  326880 uses N and 2N effective input, padded to 2N/4N transforms.
  Cache/extraction alignment max(H,N/4) is distinct from the H frame clock.
  Out-of-range PCM input is zero. Float32 PCM is widened for double windowing.
  Mode 2 only contributes center frequencies strictly less than 220 Hz.
  Peak score uses scale 2 and 1 for the two levels, compares local neighbors,
  and applies threshold float32(2*retained_bins*0.7071067812*8).
  Peaks sharing a base slot replace only on strictly greater score.
  Frequency is a three-bin magnitude centroid, not parabolic interpolation.
  spectral-frame-direct.asm 327197..3271ba confirms separate mulss/addss,
  not FMA. All boundary comparisons and float32 operations are explicit.

4. Main-executable PCM amplitude units are proven for the 16-bit path
  pcm-submit-exe-direct.asm / bitdepth-references-direct.asm:
  317fa0 checks bit depth ==16; 317faa reads context+0x258 int16 buffer;
  317fb5 sign-extends, 317fbd converts to float32; 317fc0 jumps directly to

  3180c4 loads that float buffer and 3180c9 stores into task record+0x10.
  Existing 343da0 copies this same field to the 326880 input buffer.
  Therefore this verified path uses [-32768,32767]-scale PCM floats.
  Do not multiply arbitrary normalized input by 32767 and claim an exact
  import pipeline. A new front-end adapter can explicitly decode int16 PCM
  and preserve integer values as float32; its codec/channel policy remains
  an adapter choice unless independently aligned with the original reader.
  DLL sibling corroboration: 18004ad10 produces int16; 180022770 22852..22889

5. Forward FFT sign and scaling statically established for the used power-of-two domain
  fft-core-direct.asm: 528d80 creates the real plan, delegates complex setup to
  610900 with forward flag zero. fft-config-direct.asm 6109a5..6109d2 uses
  angle=(-2*pi*i)/length. 14079e740 contains -2*pi, bytes 182d4454fb2119c0.
  Factorization 610a02..610a66 tries radix 4 then 2; power-of-two lengths need
  no other radix. fft-worker-direct.asm 6119b0 copies leaf complex samples,
  recursively transforms children, then uses inline radix 2 or calls 610e60.
  The radix 2 add/subtract and complete radix 4 function (fft-radix4-direct.asm)
  use twiddle multiplication and sums/differences with no 1/N division or
  other normalization. The sole plan-angle division does not scale samples.
  fft-core-direct.asm 528f50 recombines even/odd packed complex results:
  DC=C0.real+C0.imag, Nyquist=C0.real-C0.imag; other bins use half factors
  after adding paired spectra. These half factors undo real packing; they
  do not normalize the transform. Its real-plan twiddles are
  (-pi)*(k/half+0.5), observed 528eb0..528eee; -pi bytes 182d4454fb2109c0.
  fft-wrapper-direct.asm 326510 only mirrors conjugates after 528f50.
  Derivation: this reachable forward path is exp(-2*pi*i*k*n/N), unnormalized.
  native_fft.py reconstructs the radix 4/2 recursion and real packing directly;
  production spectral code now calls this implementation, not NumPy FFT.
  Independent dense DFT and NumPy comparisons are tests, not the proof of
  native scaling. The proof is the static reachable arithmetic above.
  This establishes scale/sign, not bit-identical native runtime roundoff.

API:
  native_configuration(sample_rate) -> {sample_rate,base_window,hop}
  iter_pcm_spectral_frames(read_pcm, sample_count=..., sample_rate=...,
                           start_frame=0, stop_frame=None)
    read_pcm(start,count) returns exactly count finite mono native-unit samples.
    Each record includes frame_index, sample_index, time_seconds, windows and
    peaks. Convert each SpectralPeak with dataclasses.asdict for JSON.
    Last spectra at each resolution are reused; input reads are bounded to 2N.

Remaining limits:
  No original-runtime differential validation. Original math-library cosine,
  sine and SIMD rounding may differ; no bit-identical equivalence claimed.
  Only forward power-of-two FFT is reconstructed, sufficient for this front end;
  inverse and mixed-radix behavior is outside the implementation scope.
  The task-specific preceding/following context padding and actual producer's
  frame-range selection are not fully reconstructed; sample-clock range is
  explicit at this API boundary rather than guessed.
  No peak-refinement, harmonic assignment, final note segmentation, or audio
  resynthesis is substituted. Those remain separate work required for a full core.
