# 音色打磨

音色打磨已与歌曲截取合并为 **音色器**，双击上一级的 **音色器.exe**。旧的 **音色打磨.exe** 已删除，构建不再生成旧 EXE。完全离线，不上传声音，不需要账号，也不使用主工作站资料库。

打开先显示本文所述的音色打磨界面。点击左侧采样列表下方 **＋** 进入歌曲截取，调整蓝线和 EQ，点 **导出到采样栏** 即可加入新片段并返回。歌曲和编辑状态保留，可以反复截取；本次关闭后不恢复。详见[合并工具说明](../tone-processor/README.md)。

这个工具把“截出的一段声音”继续加工为可以按音高演奏的采样音色。它能减少部分干扰、帮助比较多段采样、调整音高与起落、制作延音循环；无法保证把任意混音里的指定乐器无损分离出来。

## 从采样到音色

合并版中，两条蓝线均可越过另一条，始终以两者之间的区域作为保留范围；数值输入显示当前较早和较晚的时间，不固定对应某一根线。

1. **导入采样…**：选中采样编辑导出的 WAV，也可选系统支持解码的其他音乐格式。可以一次导入多段；第一段是主采样，其他段作参考。左边可换主采样、移除参考。每段最多 30 秒，同时最多 8 段；请优先使用短的单个声音。
2. 在**清理干扰**调整“减少底噪”“多段对照”“减少打击声”。松开滑杆后自动重新处理；工作期间可取消。低切去掉较低的声音，高切去掉较高的声音。默认处理较保守；“清理归零”关闭清理和频率过滤，恢复原声。图中始终保留整段主采样，清理不会把选区外的上下文从图中删掉。
3. 图下方是紧凑的试听与选区控制。点击**试听采样**，红线从当前位置向右移动并播放对应声音；再点**暂停采样**会停在当前听到的位置，继续点击从这里接着听。红线可拖动定位，顶端红色小三角便于选中；播放中拖动后继续，暂停时拖动不自动播放。勾选/取消“听原声”比较前后，位置保持对应。灰色是原声，绿色是处理后，绘图不分别放大音量。
4. **两条蓝线决定保存范围**，不再表示延音循环。拖动底部蓝色把手，或输入“蓝线保留…至…秒”，Shift 拖动可精调。选区外变暗，但保留在图中供反复调整。缩放可用“− / 倍数 / + / 全图”；Shift+滚轮以鼠标位置缩放，普通滚轮、中键拖动或下方滚动条平移。缩放和平移不改变三条线的音频时间。“去首尾空白”只调整蓝线，保留少量起音余量，不承诺消除有声干扰。
5. 检查**原音高**。自动识别估计的是整段主采样的主导周期，不代表知道你想要哪件乐器；显示的周期性数值也不是目标识别正确概率。听起来不对时，取消“自动识别”，选择音名并微调音分。不能可靠识别时暂按 C4 演奏，界面会提示。
6. 下方键盘可切换**钢琴模式 / 采样模式**。钢琴模式使用内置合成钢琴参考声，A4 = 440 Hz，不需要导入采样，不受采样的起落/音量/循环影响。采样模式用蓝线选区发音，应用当前原音高及演奏设置。判断采样原本的音高时，先用“试听采样”听原调，再用钢琴键找接近的音；采样模式用于试听移调后的效果。切换模式会停止旧的琴键试音，保存结果始终来自采样，不会写入钢琴声。
   键盘扩大为**A0–C8 完整88键**，有黑白键与音名，点击后显示音名/频率。横向滚动浏览，或使用“低八度 / 中央 C4 / 高八度”导航；初次打开居中在 C4。每次点击播放“演奏方式”中指定的按键时长，再释放。采样移调同时改变播放速度，跨度较大时可能失真。
7. 需要长音时点击**寻找延音区**，在蓝线选区内寻找可用循环。找到后开启延音循环；也可在“演奏方式”输入起止秒数与衔接毫秒数。此处起止时间使用整段图中的时间；保存时自动换算到截取后的采样。循环被蓝线截短会收拢，完全落在选区外或不足四帧会在保存结果中关闭。自动查找只是建议，仍需试听。
8. 修改音色名称，选择**保存音色…**或**导出 WAV…**，在系统文件窗口选位置。**两者都只保留蓝线之间的处理后音频**，与红线位置、缩放及是否勾选“听原声”无关。蓝线重合时不能保存。原采样、其他已导出文件不会因取消处理、移除采样或关闭工具而删除。

## 怎样选多段参考

你的“多截几段，相互比较”已经实现为一个实验方法：保留主采样的时序与相位，用参考的共同频谱特征指导抑制。参考不是直接相加，也不是被混进最终声音。

- 优先用同一音色、相近演奏方式、背景伴奏有所变化的 2～4 段，分别截出单个音。不同音高会尝试先按估计根音对齐；无法可靠识别的参考不会用于共同对照，悬停界面说明可查看结果。
- 每段都有的伴奏可能一起留下；参考中没有的气声、起音和细节也可能被削弱。较低采样率参考听不到的高频不会被当作“目标不存在”。
- 两件乐器落在同一时间、同一频率上的信息，不能凭这套方法保证恢复。错误根音会误导对齐，应先手动校正主采样，必要时移除不合适参考。
- 鼓、敲击声或有特色噪声本身就是目标时，把“减少打击声”降到零；处理越强不等于音色越好。工具不会自动归一化前后音量，以免只因变响就误判为更好。

## 两种保存结果

| 按钮 | 保存的内容 | 后续使用 |
| --- | --- | --- |
| 保存音色… | `.rstimbre`，蓝线之间的无损浮点音频、原音高、起落、换算后的循环和演奏音量 | 本工具“打开音色…”继续调整演奏方式。文件自带声音，无外部采样依赖 |
| 导出 WAV… | 蓝线之间的清理后原调 24 位 WAV，保留源采样率/声道 | 可以导入主工作站的采样音色流程，或用于其他音乐软件 |

WAV 不包含本工具的演奏包络、演奏音量或循环设置；这些保存在音色文件中。`.rstimbre` 是独立实验格式，当前主工作站尚不能直接打开；它不是已经定案的工作站文件标准。音色文件保存处理后的声音，不保存原始参考和清理过程；若要重新做提纯，请保留并重新导入原采样。

导入原件受到路径和文件身份保护，不能被导出覆盖；请为新结果使用新文件名。保存失败或取消不会损坏已有目标文件。打开另一个音色会替换当前工作，已有内容时先提示；关闭不会自动保存当前工作。

## 运行与开发

需要本目录的 `.builds/` 配套文件、Windows 10 2004 或更新版本，以及 .NET 9 桌面运行环境。不是单文件安装包。支持 1～8 声道，每段最多 16,000,000 个浮点采样值，总计最多 64,000,000 个；这些是保护本机资源的首版范围，不是永久产品限制。解码能力取决于 Windows，长文件应先在采样编辑中截短。

修改源码后运行上级的 **构建并打开音色打磨.bat**。仅检查、不显示窗口或打开真实声音设备：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File experiments/music-workflow/Build-TimbreLab.ps1 -Test
```

与前两个实验共用经过测试的解码/播放源码，构建后音色打磨独立运行，不依赖前两个 EXE。检查使用生成的音频、模拟播放对象和程序绘制的离屏图；构造/布局检查不显示窗口。实际音色质量、扬声器听感、鼠标操作和系统文件窗口仍需你体验。

## 方法与边界

清理参考 [Boll 的谱减研究](https://course.ece.cmu.edu/~ece491/homework/Boll79.pdf)和 [FitzGerald 的谐波/打击分离研究](https://dafx.de/paper-archive/2010/DAFx10/DerryFitzGerald_DAFx10_P15.pdf)；根音分析参考 [YIN](https://pubmed.ncbi.nlm.nih.gov/12002874/)。共同特征对照是本实验的启发式实现，不是这些论文承诺的任意乐器分离能力。

受控生成测试同时检查干扰减弱与目标保留，避免靠整体静音“通过”。这些合成指标不代表真实歌曲中的保证效果；特别是共同伴奏、重叠频率和复调仍需逐段听辨。本版没有语义级 AI 乐器分离、模型下载或网络服务。
