Classified native output integration

native_song_output.export_native_song keeps its existing keyword API and adds
optional assignments aligned with all input payloads. It retains source
note_index identities after selecting eligible MIDI events. Negative21c and
producer-excluded objects are rejected BEFORE ordinary pitch-cache creation;
their harmonic/noise objects still render in reconstruction and WAV stems.

write_native_midi(path, events, coordinate_bpm=...) remains compatible; optional
event-aligned assignments select real ID/name/GM program tracks. 256PPQ, native
pitch/velocity, explicit user BPM coordinates and note ordering are retained.
Channel10 requires an actual30a110 percussion key. Unknown harmonic assignments
use explicit unclassified export labels/GM0; those labels are not classifier
results. Standard MIDI Port meta events FF2101 extend the export adapter beyond
15 melodic voices: port=melodicIndex//15, channel=melodicIndex%15 skipping10.
Every native instrument keeps its own MTrk. The manifest marks this packaging
export-adapter-multiport; it is not claimed as original304bb0 sequencing.

native-song.json keeps format RipXReconstructedNativeSong/version1 and adds:
  stems: name,label,file,instrument_id,assignment_source,note_count,
         frames,sample_rate,channels and classification completeness.
  midi_tracks: label,instrument_id,program_0based,port,channel,event_count,
               explicit unclassified-placeholder status.
  classification: complete/unknown counts, native-kind counts, unknown and
                  MIDI exclusion reasons, retained source identity/functions.
  limits: MIDI and source-coverage bounds plus unmeasured resource costs.
Complete assignments/native_kind remain in every native-note-objects.jsonl row.
The200-note preview remains bounded; the full object file and MIDI stay complete.

WAV stems contain only their actual classified object group. Residual is a
separate manifest path and never duplicated in stems. Total reconstruction
preserves input-object render order. Stems rerender each object once more using
the same native kernel and output gain. This incurs an unmeasured extra render
per object. A single full-song memmap is reused sequentially; writes use65536
frame blocks, and no collection of full-song per-instrument arrays is retained.

This pass parsed Python AST and inspected source only. It did not execute MIDI
serialization, classification, numerical kernels, audio rendering, RipX, or its
GUI; no audio or image contents were inspected. No performance or audio-quality
measurements are claimed.
