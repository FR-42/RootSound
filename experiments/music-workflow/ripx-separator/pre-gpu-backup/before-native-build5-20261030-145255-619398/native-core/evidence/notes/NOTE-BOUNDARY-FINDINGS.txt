Per analysis frame, 0x4c harmonic records are grouped by uint32 at +0x34.
Records whose +0x31 bit mask 2 is already set cannot start a group.
The first record copies its raw bytes +0x34..+0x4b into the 24-byte header.
Then 48 int32 harmonic slots follow, initialized to -1.
Harmonic byte +0x49 selects slot index (harmonic-1). All matching later
records are marked with bit mask 2, including records already marked before
this scan. A duplicate harmonic slot therefore retains its LAST matching
record index. Groups retain first-unmarked occurrence order. The visible
capacity is 112 groups per frame, not a user-facing maximum musical polyphony.
Each resulting record is 0x18+48*4 = 0xd8 bytes.
The helper 0x1403449c0 is called even when the frame has zero groups. Such
empty frames must not be dropped by a later integration: they may end ongoing
state, although the exact effect remains unverified until its body is read.

Upstream 0x1403443e0 makes its first eligibility decision by calling
0x140318820(context, trajectory.type(+0x24), trajectory.float(+0x18)). It
counts only trajectory frames with (frame.flags(+0x48) & 0x82)==0 and emits
the trajectory after at least the returned count is reached. This is a
producer-owned criterion; an arbitrary minimum-duration threshold is invalid.
Output header bytes +0x34..+0x4b copy trajectory +0x10..+0x27, except type==1
overwrites +0x3c with the current frame's float +0x50. Thus group header +8
may change each frame, and must not be frozen as an entire-note constant.

native_frame_groups.py implements that exact, isolated transformation.
It returns marked input bytes separately and never mutates caller bytes.
Malformed length/harmonic guards are explicit wrapper safety checks, not
claims about behavior of the original on invalid internal data.
