# 音色结构

双击上一级 **音色结构.exe**。这是独立实验工具，原“音色器.exe”继续保留。

## 使用

1. 初始为结构分析界面。点击 **＋ 导入／截取乐曲** 进入与音色器相同的歌曲截取／EQ 页。
2. 导入歌曲或长片段，调整两条蓝线和 EQ，点击 **导出到结构分析**。蓝线内的加工结果成为总片段；没有音色打磨的30秒限制。超过10分钟的输入用磁盘缓存保存，传递后歌曲及截取状态继续保留。
3. 点击 **分解…**，在小窗口中选择分解方法。已有结果时按钮变成 **重新分解…**：始终从同一个原片段开始，方便试听比较；上一次结果和沉默状态可以撤销恢复。取消选择不会开始处理。
4. 每层有独立的 **激活／沉默** 开关。全部激活时，各层合起来近似重建输入；顶端总图不作为额外原声叠加。**原声对照**是互斥监听，取消后回到激活层的混合。
5. 各层频谱上下对齐：**横轴频率 Hz，纵轴音量 dBFS**，曲线显示当前时刻的频谱，随同步播放变化。图下的共享时间条以时间为横轴，红色播放头可拖动定位；播放／暂停和回到开始作用于所有层。沉默层的曲线仍可观察。
6. 选中一个结构层，点 **进一步分解…**，可另选一种方法，只处理这一层；新子层替换父层，其他层保持。**撤销分解**恢复上一步的层及其激活状态。最多16个当前层，保留最近8次分解的撤销。
7. 可导出选中层或所有激活层的混合为24位 WAV，保留输入采样率、声道与完整时间长度。导出激活层混合不包含原声对照开关；保存位置由系统文件窗口选择，原文件及其文件别名受到保护。

再次传入片段时，先提示替换现有分析；只有传递成功才替换，取消或失败保留当前内容。会话中的歌曲、分层和撤销不在关闭重开后恢复；需要的结果请主动导出 WAV。关闭会清理本工具的临时音频。

## 五种分解方法

| 方法 | 依据与输出 | 适合的目的与限制 |
| --- | --- | --- |
| 乐器分轨 · Hybrid Demucs | 本机已有的预训练模型，输出鼓、贝斯、人声、其他／残余 | 先按乐器大类拆开；CPU 较慢，电子音色可能归错类，仍会串音 |
| 持续声／打击声 · HPSS | 沿时间与频率做中值滤波，区分延续音高和短促宽带起音 | 拆开长音与鼓点；钢琴起音、鼓长尾可能跨层 |
| 重复伴奏／变化声 · REPET-SIM 思路 | 比较相距至少0.35秒的相似频谱，邻居中值估计共同背景 | 有重复的较长片段；重复旋律也可能进入伴奏，不等于自动找主旋律 |
| 中央／侧边 · Mid / Side | 左右共同成分 M=(L+R)/2；侧边保留 L−M、R−M | 利用双声道空间；同在中央的乐器仍混合，侧边单声道相加会抵消。单声道禁用 |
| 频谱模板 · NMF（原方法） | 学习反复出现的固定频谱轮廓，估计其每时刻强弱 | 可指定2～8层；不识别乐器，同一乐器不同音高可能分层 |

其他方法层数由原理决定：HPSS、重复、中央／侧边各2层，乐器模型4层。进一步分解受到总计16层的限制。窗口会说明不适用的声道条件或缺失组件，不会暗中换用另一种方法。

乐器模型使用项目已有 `.cache/reference-python` CPU 组件和 `.cache/reference-downloads/hdemucs_high_trained.pt`，用 SHA-256 校验既有模型后，以 `weights_only=True` 加载。默认 Python 位于当前用户 `anaconda3/python.exe`，可用环境变量 `ROOTSOUND_STRUCTURE_PYTHON` 指定已有兼容解释器。程序不自动安装／下载，模型进程禁用网络。6秒窗口、3秒步进、两端0.75秒上下文和加权交叠，按窗口处理长音频。输出保留原采样率、声道、帧数；“其他／残余”为原片段减去鼓、贝斯、人声，包含模型的其他估计与重建误差，不单独增强各层音量。

## GPU 与 CPU

方法窗口下方的设备选择只用于**乐器模型**，其余四种传统算法仍使用 CPU：

用户在本机测速后选择使用 CPU，因此程序及方法窗口现在默认 **CPU**；GPU 和自动仍可手动选择。

- **自动（GPU 优先）**：GPU 组件存在时先尝试显卡；不可用或运行失败时重新用独立 CPU 环境处理，并在进度和完成信息中说明原因。
- **GPU（失败时报告错误）**：模型参数与输入迁到显卡，检查返回张量的设备；失败时保留已有结果并报告，不伪装成 GPU 后静默改跑 CPU。
- **CPU**：明确使用原 CPU 库。

窗口异步检测显卡并显示实际名称；进度和完成状态报告实际设备。当前这台 Intel Arc 已实际验证 XPU 运行。GPU 环境为 `.cache/tone-structure-gpu/packages` 中的 PyTorch/torchaudio `2.7.1+xpu` 及锁定 Intel 依赖，CPU 环境保留；共享 Python 基础依赖来自既有目录。Windows GPU DLL 搜索路径仅对工作进程添加，不改系统 PATH 或驱动。可用 `ROOTSOUND_STRUCTURE_GPU_PACKAGES` 指定其他兼容 GPU 库目录；工作进程也能使用库所支持的 CUDA 设备。

保持 float32 推理。当前 XPU 库会将部分频谱算子交给 CPU，界面会显示“部分运算由 CPU 协同”。GPU 不保证比 CPU 快：本机30秒合成混音的独立测试为 CPU15.69秒、GPU21.51秒，各估计声部最大 RMS 差异约2.04e-8。另测混合精度更慢且误差更大，因此未采用。结果受片段、系统负载、驱动和设备影响，不是所有歌曲的性能保证；也不是实际音乐听感验收。

本机已经安装并验证，无需再次安装。重建 GPU 环境时，先关闭使用它的程序，再手动运行 `tone-structure/Setup-Gpu.ps1`（64位 Windows Python3.13）。设置脚本只从官方 PyTorch/PyPI 下载锁定组件，校验官方 SHA-256 后离线安装到项目目录，再检测真实硬件；下载可续传，所有模型权重继续复用。参考[官方 Intel GPU 支持说明](https://docs.pytorch.org/docs/2.7/notes/get_start_xpu.html)。

以下是原频谱模板方法的细节：

采用非负频谱模板分解：从片段不同时间的短时频谱学习重复／相似轮廓，在每个时间窗估计各模板的活跃程度，形成互补的频率分配掩码，再使用原相位重建声音。剩余子层通过“父层减去其他子层”计算，控制层总和与父层的差异，避免每层复制一份完整原声。频谱显示使用各声道功率的平均，不会把反相立体声简单相加抵消。

进一步分解处理选中的父层，撤销保存的是不可变层列表和激活状态。长音频、各层和中间结果存放在独立的临时磁盘文件中。频谱模板训练至多256窗，重复方法至多1536参考窗并使用64频段相似性描述，每帧最多7个非相邻参考；HPSS只缓存一个局部邻域。传统方法和乐器模型按窗口生成结果，工作数组不随总时长无限增长；长歌曲的磁盘用量和处理时间会增加。处理支持取消，取消模型会终止子进程并清理临时结果。

参考思路：[NMF](https://www.ee.columbia.edu/~dpwe/e6820/papers/SmarB03-nmf.pdf)、[HPSS](https://dafx.de/paper-archive/2010/DAFx10/DerryFitzGerald_DAFx10_P15.pdf)、[REPET-SIM](https://ismir2012.ismir.net/event/papers/583_ISMIR_2012.pdf)、[本机模型对应的官方 torchaudio 文档](https://docs.pytorch.org/audio/2.7/pipelines.html#hdemucs-high-musdb-plus)。传统方法为本工具的有界近似实现，不是论文原程序。

**结构层不等于准确乐器分轨。** 固定频谱模板可能按音符、谐波或共同的频率结构分组；同一乐器可能跨层，重叠乐器可能留在同层。互补分配保证不反复叠加完整原曲，不能保证某件乐器完全没有串音。曲线表示当前短时间窗的估计音量，也不代表无限频率／时间精度。
