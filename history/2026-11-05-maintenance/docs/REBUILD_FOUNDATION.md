# RootSound 第一阶段基础设计建议

创建：2026-10-22；更新：2026-10-23。状态：**组织与主要分工按已确认原则；下文分别记录设计建议与当前可调整实现，不将首版细节视为最终定案**。

本文件细化[新架构草案](REBUILD_ARCHITECTURE.md)中第一条可用创作流程需要的边界。它遵守已经确认的组织、自由交流、公共保管与独立工程规则。用户已批准声音运行独立为后台平行模块及其与创作模块的主要分工；对象形态、内部部门和操作细节仍是建议，不因写入文件成为用户定案。

2026-10-23 当前以音色、乐句、歌曲的手动创作为重点，共创已暂时隐藏。工作区精简、实体栏与拖入、按实际引用数决定覆盖/分离、歌曲后期和工程往返已整合；具体自动检查与构建依据见[重建进展](REBUILD_PROGRESS.md)。按 N13 不读取屏幕或操控桌面，实际界面与听感仍待验收。`RootSound.exe` 是日常入口，`RootSound.bat` 保留一键构建打开。桌面宿主、存储和声音运行适配器仍可替换；歌曲默认各乐句保留原速由用户确认，当前坐标编码、数值上限和工程容器细节仍可调整。

新实现位于 `src/workstation/`；旧原型已完整隔离在 `legacy/prototype/`，使用独立启动与验证命令，不进入新项目构建。旧实现与旧文件快照用于恢复和参考，不是本文件公共规范的依赖或默认兼容目标。

## 1. 声音执行的归属

### 1.1 已确认：后台平行模块“声音运行”

声音运行负责让已表达清楚的声音内容按时间实际执行：单个声音试听、乐句试听、歌曲播放、设备输出与离线音频生成。它与其他模块平行，按共同规范自由交流，具体工作由其最次级单位执行。

**用户已批准：**声音运行类似界面渲染，作为后台模块承担“全局声音的海关”。这里的“海关”指全项目实际发声与音频渲染的统一公开运行边界，统一维护相关播放状态、时间执行与设备输出；创作模块通过共同规范使用这些能力。

后台表示它在创作界面背后提供能力，不要求用户每次试听先打开一个声音运行窗口。它与其他模块的组织地位相同；同级自由交流仍然成立，无需经它批准或转发其他模块的交流。创作内容的含义、编辑与具体处理方法仍按明确职责归属，不因统一运行而全部集中到这里。此称呼也不沿用旧原型把“海关”专指音高换算的范围。

下表保留决定时比较过的方案，作为设计理由：

| 选择 | 能带来的好处 | 主要问题 |
| --- | --- | --- |
| 由歌曲编排统一负责播放 | 歌曲播放靠近编排内容 | 单个音色或采样试听会依赖歌曲模块；容易把运行能力与歌曲编辑绑定 |
| 各创作模块分别管理时钟和设备 | 模块可独立启动试听 | 同时试听、音量、停止和设备变化容易出现多个互相不一致的运行状态 |
| 增加声音运行模块 | 各种创作内容可独立试听，播放和导出共用明确的执行边界 | 需要清楚区分创作含义、处理算法和运行职责，防止成为新的万能模块 |

已采用第三种的模块地位和主要分工。全部音乐算法的集中、内部部门划分和第三方插件系统均不属于本次批准范围。

### 1.2 主要分工与执行细节建议

**已确认的主要分工：**创作模块负责内容含义、创作选择与编辑；声音运行负责实际试听、播放、设备输出与离线生成。下表进一步描述候选输入与实现边界，具体规范仍需验证。

| 单位 | 负责决定的内容 | 交给声音运行的内容 |
| --- | --- | --- |
| 音色制作的执行单位 | 如何构成和修改音色、参数的专业含义 | 可执行的音色描述及所需素材；或符合规范的声音处理能力 |
| 乐句谱写的执行单位 | 哪些声音演奏哪些音符、起止与力度 | 已解析的演奏安排、声音引用与试听范围 |
| 歌曲编排的执行单位 | 片段位置、轨道关系、混音与效果意图 | 歌曲范围内的声音安排和处理连接 |
| 后期处理的执行单位 | 最终处理设置、输出要求 | 已确认的处理安排、生成范围及音频格式要求 |
| 采样获取的执行单位 | 怎样取得外部声音 | 可用的录音内容或符合规范的持续声音输入 |

这里的“可执行”是指运行单位能理解所用处理方法和参数，或者能按公开能力调用相应执行者，不是随意传入可执行脚本。

每种处理方法有明确的实现归属。首版可以由声音运行的最次级单位实现少量内置发声与处理基础，音色制作的最次级单位使用它们构成音色。将来若有其他模块提供专用执行能力，也必须通过共同规范接入，不能导入其内部代码。

运行单位使用另一个单位公开的能力，不改变那个单位的组织上级，不构成多上级共享部门。

### 1.3 按需要设置的内部职责

以下是职责示例，不要求预先创建全部部门：

- **播放会话**：记录一次试听或播放的内容、范围、位置和运行状态。
- **时间执行**：把安排的事件放到实际执行时间，保持播放连续。
- **声音处理**：执行已支持的发声、连接和处理方法。
- **设备输出**：将声音送往实际设备，报告设备状态。
- **离线生成**：不依赖现场播放速度，将确定的内容生成音频数据。

一次试听不等于一个新歌曲工程。单音色、乐句、歌曲均可建立各自的播放会话。

多个创作会话怎样同时响，仍需完整工作站的用户体验设计。当前验证采用新试听替换旧试听；一段乐句内部的多个音符可以重叠和同时发声，共用一个会话与设备时钟。不能让两个模块各自设置一个互相不知道的“全局正在播放”。

### 1.4 一致性与实时边界

- 编辑中的创作内容由公共管理部分保管；播放会话状态由声音运行维护；界面保存选中、滚动、拖拽等临时显示状态。
- 开始播放时取得可执行的一致内容版本。变化通过公开的更新能力进入会话；会话报告实际采用的状态。
- 连续试听调整可先编译临时内容，在松手后才保管一次编辑；取消或写入失败恢复已保管内容的计划，不能顺带覆盖库中音色。
- 声音执行不在每个处理时刻等待磁盘、账号、网络、AI 或用户界面响应。需要的内容缺失时明确报告准备中或不可用，不悄悄漏奏。
- 最高指挥中心可协调任务与资源，但没有合成、效果计算、歌曲解释或逐采样点转发职责。
- 离线输出和试听尽量使用相同的声音解释与处理方法。两者出现差异时应可验证，不能假定保存了参数就必然相同。

当前 `sound.update` 公开能力保留播放会话身份、开始时间与当前位置，按实际设备时钟更新仍在发声和未来的音符，以约 5 毫秒交叉平滑切换。声音的音色、音量与包络，乐句的速度、力度和音符操作，以及歌曲的混音、静音和片段移动均接入此能力；连续输入按显示帧合并。停止、切换会话或取消操作后，旧排队更新不能误写新会话。当前实现每次有效更新重建剩余振荡器，仍需后续专业实时引擎与实际听感验证。

## 2. 最小内容模型

### 2.1 公共内容外壳

公共管理需要理解“这是什么、是哪一份、依赖什么、怎样保存”；音色与乐句等内容的专业解释由其负责单位提供。

| 信息 | 含义 |
| --- | --- |
| 内容标识 | 内容的稳定身份；改显示名称不改变身份 |
| 内容种类与格式版本 | 选择正确的读取及解释能力 |
| 所有者单位 | 负责该内容专业含义和编辑能力的组织单位，支持分类整理；不自动等同于用户账号或文件夹权限 |
| 保存修订 | 同一内容的一次已保存状态；用于识别更新和避免无意覆盖 |
| 依赖引用 | 列出需要的音色、采样、音高解释和处理配置等内容 |
| 显示资料 | 名称等面向用户的信息 |
| 专业内容 | 音色、乐句、歌曲等各自需要的数据，由对应公开规范描述 |

不把所有对象集中成一个可以随意修改的共享对象。也不要求公共管理实现音色制作或理解所有未来算法。

### 2.2 第一条流程所需的内容

| 对象 | 首版需要表达的最少信息 | 暂不强制的内容 |
| --- | --- | --- |
| 采样 | 原始音频、可读取格式、声道与时间信息、来源说明 | 不为所有设备格式先建立统一转换系统 |
| 音色 | 发声/采样方法、参数、包络等配置及依赖 | 不沿用旧振荡器数量和参数范围限制 |
| 乐句 | 自身长度、声音角色、每个角色引用的音色和演奏事件 | 暂不强制增加独立的“工程乐器实例”对象 |
| 歌曲 | 独立轨道、片段引用、起始位置、源内容范围，以及需要的处理设置 | 不固定“一行一个乐句”，不要求所有乐句同长 |
| 工程 | 创作目标、所用内容及依赖、可恢复的工作状态 | 不要求所有工程都包含歌曲 |

“声音角色”指一段乐句中某一部分用什么声音演奏，例如贝斯部分。第一版可以直接引用音色；需要多个乐句共享工程内乐器调整时，再明确是否引入独立的使用配置。不能悄悄把音色定义重新复制进每个乐句。

片段是某段内容的一次摆放；源内容的长度、歌曲上的位置和此次播放范围分别表达。拉长、裁剪、重复播放的具体交互仍需设计，不能用一个长度字段兼任全部含义。

### 2.2a 当前歌曲范围与名称约束

公共管理接受各音乐所有者提供的引用适配器，解释依赖位置与合法目标；它管理歌曲归属、
素材身份和名称，不自己解释音符或制作声音。实际应用装配显式启用这项项目策略。
不同歌曲的依赖闭包（包括原始采样）使用不同身份，同歌重复引用同实体仍共享。
从公共起点采用时保存来源图修订到本曲实体的映射，跨重启重复采用不制造同一来源副本；
源图变化才可形成新版本。当前选择器隐藏他曲素材和已有本地副本的公共原件。

同歌同类名称按去首尾空白、NFC 和忽略大小写比较。手工冲突保留稿件并报错，自动复制
和派生按需加数字；未摆放但仍保留的本曲素材也保留名称。归属、重写后的引用、嵌套暂存
及最终事务历史一起提交，撤销重做按实际提交图恢复；另存歌曲与工程导入建新范围。

旧库只读恢复保持原字节，相关编辑时隔离旧共享图；旧历史允许恢复历史原状，再次正常
编辑重新隔离。旧共享实体的直接覆盖不能跨歌生效，须从具体歌曲位置编辑。
这是歌曲范围的当前落实，未来单声音等独立工程形态不在本轮冻结。

公共起点区现也按种类保留唯一名称。已保存实体和其来源稿按身份合计一次，独立新稿
另占名称；人工改名或显式命名事务冲突时拒绝，自动生成、导入和派生补数字。所有业务
方必须读回实际提交的内容名称，不能返回规范化前对象；历史重做不能恢复后来被占用的
公共名称。公共区和各歌曲的名称范围相互独立，不变成整个资料库全局禁止同名。

### 2.3 时间、音高和单位：先定约束，暂不冻结编码

第一条声音执行路径开始前，需要选定具体表示。当前建议先约定：

- **时间要说明参照。** 音乐中的相对位置、实际录音的秒数或采样位置不能靠裸数字猜测。原始采样信息与音乐速度分别保存。
- **存储精度与编辑吸附分别表达。** 拖动时使用的刻度不应限制全部已保存内容的精度，也不能用缩放改写音符数据。
- **音高要说明解释方式。** 普通旋律、微小偏移、滑音与非传统声音需要有明确含义；不在各模块暗藏十二平均律公式，也不直接继承旧“槽分”作为大众界面单位。
- **物理声音信息与创作坐标要能对应。** 负责解释的执行单位在运行时完成转换，公共管理保存足够的解释信息，最高指挥中心不负责音乐换算。

这些约束允许乐句使用拍的相对位置、音频使用秒/原始采样位置；音高使用带解释方案的数值，或在确需时表达明确频率。当前乐句采用的具体表示见下一节，未来坐标扩展、调音方案与可转换范围仍需验证，不在此冻结全部数学模型。

### 2.4 当前乐句实现采用的最小表示

本节记录已实现的第 1 版试验规范，属于可调整的实现选择，补充前文的设计约束。

| 信息 | 当前表示与归属 |
| --- | --- |
| 乐句身份与引用 | 公共管理保管 `rootsound.phrase` 内容及独立编辑稿；每个声音部分只保存音色身份，顶层依赖恰好列出所用声音且不重复 |
| 音乐时间 | 乐句明确标注以拍为单位，保存自身长度、速度及每个音符开始与持续的拍数；乐句模块将其转换为实际执行秒数 |
| 物理音高 | 每个音符保存明确频率 Hz，以及独立力度；声音模块接收这些输入，负责解释其已有音色 |
| 键盘入口 | 当前提供十二平均律，以 A4 为 440 Hz；一个连续滚动窗口包含 20–5000 Hz 内全部 96 个键（E0–D♯8），不按音区隐藏。非标准频率显示在最近行而不量化数据；键盘换算由乐句模块公开提供 |
| 网格与存储 | 界面提供每拍、半拍、四分之一拍或自由时间落点；显示和吸附不重写所有已存音符，水平移动也不强迫原音高落入键盘格 |
| 运行安排 | 音色模块通过公开能力解析每个被引用声音，乐句模块形成带开始时间的完整事件序列，声音运行预先检查后统一执行；没有声音算法复制进乐句或界面 |
| 编辑与恢复 | 编辑稿与其最多 64 步撤销重做历史同次原子写入，跨重启恢复；构造空乐句模块不偷偷创建声音或空稿；乐句保存与重开保留实际引用 |
| 批量编辑 | 多选与框选属于界面状态；成组新增、移动、力度修改和删除经乐句公开能力整体校验、一次保存、一步撤销；复制生成新音符身份 |
| 显示操作 | 横向缩放不改音乐；拖动期间即时更新当前试听，松手提交一次，取消或失败恢复已保管内容；内部剪贴内容保留时间间隔、频率、长度与力度，不隐含复制声音 |
| 交换文件 | 当前没有乐句交换格式；`.rssound` 携带单个无外部依赖的电子音色，不承担乐句或完整歌曲工程打包 |

例如同一拍上的两个音符会同时演奏，速度改变只改变执行时间，不改音符的拍位置。比起音时间更短的音符按其实际时长进入收音，不把音符长度硬改成起音时间。当前参数范围见[重建进展中的实现表](REBUILD_PROGRESS.md#已确认与可调整实现)，这些范围不声明为项目永久上限。

未知版本或字段、缺失声音、重复音符身份、不一致依赖和超出乐句结尾的音符均会明确拒绝，原资料保留；不会省略错误部分后假装完整试听，也不会缩短乐句时自动裁掉音符。当前音乐编辑是可恢复的基础工具，尚未实现共创或降低全部谱写负担。

恢复最新乐句时，构造模块只保留其身份，不先修改数据。若该稿的专业内容暂不支持，读取结果带有明确问题和原始稿件，停止提供该稿的编辑/试听；用户仍可打开正常稿件或新建，原问题稿继续留在公共库。这个局部恢复边界不放宽整个资料库的结构完整性检查，坏库仍须明确报错并保留文件。

### 2.5 当前歌曲与已保存内容的公开解释

歌曲编排现为独立执行模块。第一版内容保存歌曲速度、明确的播放速度规则、长度、轨道及乐句片段。片段只记录自身身份、引用乐句身份和开始拍位置；轨道记录名称、音量、左右位置、静音与单独播放，不复制源乐句的音符或音色参数。

**用户已确认：歌曲默认各乐句保留原速。** 歌曲中也可明确选择“跟随歌曲速度”。例如原速 90 拍/分钟的乐句放入 120 拍/分钟的歌曲，默认仍以 90 播放，选择跟随后才以 120 播放；源乐句保存内容保持不变。歌曲解释时间线位置与混音意图，乐句公开能力解释自身内容与演奏时间，音色公开能力解释发声参数，声音运行负责实际执行。

乐句的只读公开能力可列出已保存内容、验证并读取某一乐句、编译其演奏计划。省略速度覆盖时使用乐句原速；只有明确传入速度时才覆盖本次执行。歌曲以此能力取得一致的可执行结果，不直接读取乐句内部实现。编译不修改、保存或嵌入源素材。

当前处或联合应用使某个位置采用修改后的乐句时，其时长可能改变，歌曲按该位置实际引用的保存内容计算有效范围。既有编排超出当前新增范围时仍保留可编辑状态，允许移动或移除片段修复，不能因为依赖增长把整首歌锁死。第一版限制及其暂定性质见[重建进展](REBUILD_PROGRESS.md#已确认与可调整实现)。

### 2.6 试听与普通音频交付

声音运行已提供实际离线生成能力，即不必按真实播放速度录音，而是使用离线时钟生成确定的音频。试听和导出共用发声图、音量变化与左右位置处理；当前界面交付 48 kHz、24 位、双声道 WAV，包括音乐范围与尾音。WAV 不保存可编辑音乐关系，不能替代完整工程格式。

界面发起导出时先捕获完整计划，后续修改不回流进正在生成的结果。任务提供进度、取消和失败；过时试听请求不能覆盖新状态。原生文件接口在可靠写入后才返回保存成功，浏览器接口只能返回下载已发起；取消文件选择不报告成功，也不改变音乐内容。

基础导出由现有声音运行与文件公开规范协作，不为尚未提供最终效果处理的“后期处理”预先创建空壳。这不改变将来后期模块负责最终处理与输出意图的组织设计。

## 3. 引用、编辑稿与保存

### 3.1 工作引用与导出内容

- 制作中的工程通过稳定标识引用内容。同歌复制共享引用；普通修改保存时按实际使用位置计数，零或单引用覆盖，多引用才沿当前路径生成必要的新身份，不改变未选中的位置。
- 一次播放、后台处理或导出可以在内部固定本次采用的修订，使任务期间使用一致内容；这不自动增加一个“用户锁定所有资产版本”的产品规则。
- 导出的完整工程文件把本次采用的内容收齐，包内引用由包内内容满足；不会因为源库后来覆盖而改变。

### 3.2 当前处修改与按位置联合应用

用户最新确认：单引用直接覆盖，多引用才为当前这一处创建实体，必要祖先同样判断。已保存歌曲与工作稿相同位置合算一次，临时细调稿不算新引用；普通乐句稿新增或换入的音色引用仍计数。嵌套编辑先暂存到外层提交，取消不提前改原实体；显式另存始终新建，联合应用仍由用户选位置。

覆盖操作的撤销同时保护未改动的已保存上游快照；若用户后来保存或改动上游，旧撤销明确拒绝，避免改变新版本。这个保守冲突边界不等于无限历史或已保存版本永不改变；当前可调整实现和自动依据见进展。

1. 从歌曲的具体片段进入乐句，从乐句的具体声音部分进入音色。公共管理保存独立编辑稿、来源和完整使用路径，界面显示当前位置；执行单位仍负责解释和修改自己的音乐内容。
2. 复制只复制相应内容和引用，不预先复制所有依赖。当前处保存时，根据实际使用路径分离所需层级。例如同一乐句出现三次，修改第二处的音色，需要新音色及新乐句，再只调整第二处片段引用，不能仅依据音色的直接引用数量判断影响。
3. “应用到其他位置…”按作品展示实际位置，由用户选择共同采用修改的几处。选中位置连接到同一修改结果；未选位置继续引用旧内容，不覆盖原素材来间接影响全部使用者。
4. 嵌套音色编辑中的联合范围先暂存在父乐句稿中；保存父乐句时才统一提交外部位置。取消父级不会影响外部作品，并清理不再需要的临时派生内容；已经被其他作品采用的内容保留。
5. 新素材、必要上层分离、所有选中位置与历史作为原子事务提交，即全部成功或全部保留原状。修改过程中不因每次拖动不断创建新素材；取消或保存失败不产生半套修改。
6. 从素材库直接打开音色或乐句，零或单引用可覆盖，多引用因没有指定当前位置而另存新素材，不擅自替换引用。歌曲自身保存更新当前歌曲，明确另存与工程打包分别处理。

所有编辑稿仍归公共管理保管；声音、乐句和歌曲模块通过共同引用规范各自解释可替换的位置，公共管理不推断音乐正文。

### 3.3 最小冲突处理

建议保存请求同时说明“我基于哪次保存状态修改”。如果内容已经被另一个编辑位置改过，则返回变化事实，不直接最后写入覆盖。首版可提供重新查看或另存，不预先实现自动合并。

按位置应用针对确定的源素材、路径及选择范围。源素材、父级或其他选中位置在选择后发生变化时，拒绝使用旧条件提交；保留编辑稿，让用户重新检查位置，不静默覆盖外部修改。

修改冲突检查只保护同一内容的一致保存，不是同级单位交流前向最高指挥中心申请许可。两个模块可以自由交谈，但不能因此无意覆盖彼此的编辑结果。

当前乐句和歌曲撤销按具体编辑稿处理，每稿最多 64 步历史，与音乐内容在公共库中同次原子写入，完整退出后恢复过去与未来分支。旧库没有历史时，从更新后的编辑开始积累。写入失败不推进内容或历史，新修改清除重做分支；校验使用的稿件若已变化，不用旧快照覆盖它。

按位置应用将新素材和引用调整记为一次复合历史操作，可一起撤销、重做。联合应用按当次选中范围整体恢复，包括该次更新的外部已保存作品；若这些外部目标后来被修改，则拒绝撤销或重做，不能以历史快照覆盖新的创作。当前歌曲在应用后另行保存的版本不随编辑稿撤销被倒改，它仍使用的派生素材也不能删除。音色参数现已有独立持久撤销入口；任意模块操作的统一历史和无限历史仍不在当前范围。

### 3.4 公共素材查询与副本

公共管理不解释专业内容，提供分类、名称搜索和使用关系查询。当前“素材管理”按歌曲当前工程查询，包含当前歌曲依赖和显式成员的传递依赖；同一实体的有效编辑稿替代其已保存状态展示，不重复列卡。只为旧保存或撤销保管的实体不属于当前清单，其他歌曲和公共起点也不混入。使用关系只沿这份当前清单追踪；编辑来源不被误当成播放依赖。没有当前歌曲时，素材管理为空，独立创作仍可在所属工作区打开。

“另存副本”核对原素材的预期修订，一次写入新内容和对应编辑稿；当前歌曲内还将其列入显式成员。即使未放入编排，副本及其依赖也出现在当前清单并随工程保存。下层依赖继续共享，原作品及已有引用不改变；写入失败不留下半份副本。成员关系由公共管理保管，不把历史保留身份自动当成成员，也不把普通复制暗中变成复制所有间接依赖。

### 3.5 完整工程文件与文件保存

当前 `.rsproject` 保存歌曲当前稿、显式工程成员及这些根的全部传递依赖，包括乐句、
基础合成或采样音色及原始采样，保留完整音乐参数。没有附加成员时维持 v1 封装，
有成员时使用 v2 的 `memberIds`；读取同时兼容 v1/v2。v1 必须恰好是歌曲闭包，
v2 必须恰好是歌曲与成员的联合闭包；不夹带其他歌曲、旧保存、撤销历史和应用偏好。

各音乐所有者通过公开引用能力验证自身内容、目标类型并重写引用；公共管理只
收集和校验依赖图。打开时给所有内容分配新身份，保留包内共享关系，一次事务
写入内容、成员关系与根编辑稿；同名、同原标识或重复导入都不覆盖已有作品。缺失、
循环、未被歌曲或成员闭包覆盖的孤立内容、不支持的版本与引用类型会在写入前拒绝。
当前清单中尚未完成的乐句或音色稿，包括成员的修改，须先完成或取消，不能只打包旧状态。

歌曲主“保存工程…”与 Ctrl+S 共用文件流程，先提交当前输入，再捕获快照、打开位置选择；
空歌曲也可保存。Windows 可靠写入后才返回成功，取消和错误不报成功并保留创作。
本机编辑稿持续落库用于恢复，与用户主动选择位置保存的工程文件分开；自动恢复不代表
已经更新文件，后续修改须再次保存。浏览器验证版只能报告下载已发起。

当前上限为 32 MiB、8192 份内容，属于可调整实现选择。这里只承诺目前已实现的
音乐模型；第三方处理器和未来模型需要另行扩展与验证。兼容 RootSound
可在空素材库中恢复、继续编辑；原库后来修改不改变已保存的工程文件。
`.rssound` 保持单个无依赖电子音色用途，WAV 用于普通播放。

桌面公共资料库上限同步提高为 128 MiB，避免可接受的 32 MiB 工程受旧 16 MiB
库限制而无法落地。目标库容量不足时仍明确失败并保留原内容，不删除其他作品。

### 3.6 离线共创会话的第一版（当前暂时隐藏）

独立 `co-creation` 模块通过公共能力生成音色、乐句与试听计划，具体规则在其最次级
执行文件中，装配层和界面不制作音乐。会话是公共素材管理保管的 `rootsound.co-creation`
编辑稿，引用起点乐句与当前成果；`source`、`current` 是共同位置编辑规范中的稳定位置。
普通细调沿 `current` 进入现有乐句和声音编辑能力，保存后重新引用独立结果，不覆盖起点。

每轮只给三个本地规则方向。候选图纯内存生成，试听交给乐句、音色公共编译能力和
声音运行。只有选中的音色、乐句与会话更新一次原子提交，旧候选不会堆进公共素材库。
选择使用包含当前音乐依赖的状态标记，细调或外部变化后不能沿用过时选择。
首次选择可添加少量低音和铺底；后续沿用最新音符，不反复叠伴奏。当前方向主要改变
音色表达，不识别调性、理解文字或学习偏好。

会话有跨重启撤销重做；成果已被歌曲采用时，撤销保留其依赖。转入歌曲使用歌曲公开
能力，一次可靠写入新歌曲稿，旧歌曲稿保留。未完成的细调先完成或取消，才允许换起点、
选择新方向、撤销或转入歌曲；返回相同细调位置会恢复已有稿，避免隐藏的重复编辑。
当前工程文件携带歌曲使用的完整音乐，暂不携带共创会话和探索历史。

### 3.7 采样获取的第一版

独立 `sampling` 模块通过文件、解码和录音三个公开端口获取声音。结果是无下层依赖的
`rootsound.sample` 素材，原字节、来源和解码试听信息由公共管理保管，不存原路径引用。
原音频不转码；未压缩 PCM WAV 按其时钟解码，其它编码由环境离线解码，试听信息不冒称
原文件位深或采样率。录音用输入处理器收集单声道 Float32 样本，输出 WAV 格式 3 与 fact
区块；关闭回声、降噪和自动增益是采集请求，不承诺设备无处理或硬件原生位深。

完成获取后的待保存内容留在内存，切换工作区保留，完全退出前需要保存。保存一次原子
创建独立内容，不同时创建一份重复大编辑稿，也不把音频放入撤销历史。保存失败保留待存
内容，改名另存创建新身份。替换未保存采样前提供保存、放弃或返回；只读库内试听不替换
待保存内容。素材分类和启动入口同时支持采样获取。

试听使用全局 `previewAudio`，与合成试听共享设备、会话身份、替换、停止和失败生命周期；
迟到的解码结果在调用运行能力之前检查取消状态，不能打断新工作区的音乐。采集本身是
输入通道，处理器输出保持全零，不提供旁路监听。取消、离开、挂起或设备断开释放输入；
权限迟到时立即关闭返回的轨道。桌面仅允许受信本地页面进入麦克风正常授权流程，其他
权限继续拒绝。没有自动授予权限，也没有在开发验证中实际访问麦克风。

暂定单文件 16 MiB、解码后 120 秒/64 MiB、录音 30 秒。当前 base64 原件存入 128 MiB
公共 JSON 库，有约三分之一编码开销；长期二进制素材保管应由公共管理扩展，不能退回
外部路径。未压缩 WAV 在分配 PCM 前检查边界；其它压缩编码须在完整离线解码后核对范围，
极长压缩音频可能先占较多内存。这些是当前适配器限制，不能当成最终专业采样规格。
哼唱识别和采样音色随后分别落实于 3.8、3.9；完整采样编辑与系统回录仍待实现。

实现依据：[Web Audio](https://www.w3.org/TR/webaudio/)、
[Media Capture](https://www.w3.org/TR/mediacapture-streams/)、
[WebView2 权限](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2permissionstate)。
录音处理器作为独立本地构建资源提供，避免小资源内联改变其来源；
[Vite 资源内联设置](https://vite.dev/config/build-options.html#build-assetsinlinelimit)已通过当前安装版本核对，
实际桌面资源与被测试处理器的 SHA-256 一致，具体构建和自动验证见进展记录。

### 3.8 单人哼唱转为可编辑旋律

独立 `melody-recognition` 模块接收共同 PCM 和稳定来源标记。分析执行单位在后台
worker 内进行降采样、周期性音高估计和时间分段，输出秒位置、持续时间、连续 Hz、
力度、周期性可信度和少量提示。它不访问麦克风、播放器或存储，也不推测歌词、调性
或 BPM；不是人声分离。当前面向最多 30 秒单人清唱或哼唱，工作音域约 55–1400 Hz。

识别前先保有输入快照，声道按交流分量能量选择最强的一条，避免反相平均抵消，但不能
保证选出有旋律而非有伴奏的声道。帧分析做能量门控与周期性判断，保留休止，以中值和平滑
抑制短暂音高抖动，并识别音头和持续音高变化。连续滑音、颤音当前归纳为平直音符，
不能声称保留了完整音高曲线。可信度表示周期性清晰程度，不是人声或音符正确率。

结果和试听候选仅在内存中。确认时由音色模块的纯构造能力准备音色、由乐句模块的
`preparePhraseFromSeconds` 转成乐句，公共管理一次提交两份内容和乐句稿，重复确认
复用同一身份。默认 120 只把秒映射成拍坐标，播放时序、原有停顿和物理音高不量化；
用户随后可以精细编辑。无需先保存原录音，不将其暗中写库或作为合成乐句的依赖。

共创启用时的历史细调入口先建立旅途；当前暂停共创，识别确认后直接打开可编辑乐句，
不创建隐藏旅途。若交接失败，保留已确认结果并允许重试，不重复制造乐句。原采样
的 `audioToken` 在新完成音频时改变，改名和保存不改变；换源、开始新获取、离开或取消
会终止分析，采用和试听前仍核对标记，不能把迟到旧结果套到新来源。

验证使用已知音高、谐波、噪声、颤音、滑音、音头及休止的合成 PCM，并覆盖工作音域
两端，实际完整流程和独立打包 worker。它们不等于真实人声、浏览器窗口或麦克风的
体验验收。算法参考 [YIN 原论文](https://doi.org/10.1121/1.1458024)，实现及限制可以调整；
未来更强识别、复调与曲线表示不能以当前基础算法已完成为由被视为现成功能。

### 3.9 采样成为可弹奏音色

`rootsound.timbre` 新增 `sample-instrument` 模型，仍属于音色制作，而不让采样获取
承担乐器算法。音色只记录原始采样身份、起止秒位置、原始 Hz 音高、起落与音量；
歌曲→乐句→音色→采样保持层层引用。裁切不改原文件，普通当前位置修改沿用既有
按路径分离与联合应用规则，同一首歌的多个音色仍可共享同一个原始采样。

异步解码由采样模块的公开 `SampleAudioPort` 承担。音乐所属模块显式提供准备能力，
界面在试听或 WAV 导出前等待，随后同步编译和调度，不在每个音符开始时读磁盘或解码。
编辑结构读取不依赖热缓存，冷启动也可先编辑。缓存按素材身份与修订失效；公共管理
提供不含大原件正文的轻量元数据，避免每个音符和滑杆输入都复制 base64。界面离开、
换作品或新试听后隔离迟到结果，准备失败明确报错，不悄悄使用基础合成替代。

执行计划通过共同的 `PlayableNotePlan` 表达基础合成或已准备采样。PCM 只属于运行数据，
不写入音色、乐句或撤销历史。实时和离线沿用同一发声图，唯一声源完整校验和快照，
同设备缓冲按需共享并释放；指纹只比较小参数与内容摘要，不为每个音符序列化 PCM。
实时改变参数按音符当前年龄从相应采样位置接续，保留歌曲时间线。

单次模型保持原行为；新增采样模型 v2 可声明原采样秒坐标的循环区间，完整落在播放
范围内。先播放开头，再在区间内重复直到音符收音结束；实时接续计算原音符年龄及
循环相位，不从头重放。未开启循环时仍以原件末尾或收音完成中较早者结束。倍率为
目标音高除以原音高；移调仍同时变速。循环接缝平滑、保持时长移调、频谱编辑、多采样
键位/力度映射和完整效果链未实现。调度语义参考 [Web Audio 采样循环规范](https://webaudio.github.io/web-audio-api/#looping)。

引用适配器暴露稳定 `sample` 位置，工程管理自然收齐原件并在导入时重映射共享引用。
共创候选保留手工采样音色及其依赖，方向变化可通过合成伴奏表达；试听不发布原件副本。
当前工程收录原编码文件，PCM WAV 由 RootSound 自带解码；其他压缩编码换机仍需要
目标运行环境具有相应解码能力，不承诺任意编码都可跨环境播放。

### 3.10 后期与当前作品实体栏

后期是独立公开服务，歌曲保存可选的总音量、淡入/淡出秒数和启用状态，编译时交后期
形成共同执行计划的最终输出参数。实时与离线声音图使用同一总线，淡出终点包含自然
收音尾音；超长且重叠的淡入淡出按全长等比例收缩、连续相接。当前总音量 0–100%、
淡入淡出各 0–30 秒是可调实现。现有全局峰值保护继续作用，原声对比不改原音色/乐句。

实体查询模块只读公共元数据和依赖，按当前工程清单列出音色/乐句，工作稿与来源实体
合算一份，历史保管不进入本曲列表；公共起点只在实体栏另列，不解码大采样。
界面按实际编辑稿归属查询，避免显示他曲私有素材；拖放只携带版本、
种类和身份，接收端重新验证可用范围，音乐所有者执行新增声部或摆放。空稿音色拖入
创建乐句，已有乐句追加声部；歌曲拖入沿用正常原子添加与撤销。内部模块边界没有因
界面共享素材栏而合并。

### 3.11 可编辑电子合成与统一音色入口

用户确认真实乐器与电子音色并重，可以分阶段完成，从入口和结构上统一。当前共用
音色身份、引用、保存与声音运行边界；按来源显示不同编辑工具，不强行共用所有控件。
“新建音色”始终可见，可浏览试听电子起点或转入采样；取消浏览不结束原位置编辑。
真正选择新建时才处理未完成的当前位置修改，错误不继续创建或丢弃原稿。

新增 `synthesizer` 内容模型 v1，仍由 `rootsound.timbre` 所有者解释：最多四个稳定身份
的声源，含波形/噪声、开关、半音与音分、独立音量；完整起音/回落/保持/收音，明暗
滤波和音高回落。当前十二个起点返回独立参数，试听不落库。数量与范围是可调整选择，
不是完整合成能力的永久上限。旧三种配方只读展示等价参数，实际编辑才转新模型。

音色所有者把这些设置编译到公共执行计划，运行端只执行波形、噪声、滤波、频率和
包络调度。噪声缓存按设备复用，滤波/噪声资源参与释放；实时与离线同图。ADSR 短音
从实际达到的音量收音，实时重建接回原音符年龄；独立声源音量按比例限制混合幅度。
滤波共鸣附加保守衰减，暂非专业响度或压缩处理。上述底层能力不在装配层实现。

基本与采样音色的名称、参数和循环修改经原子历史保管，支持跨重启撤销；当前位置的
最终引用应用仍归父级复合历史。预览临时值不写历史，松手一次写入，失败恢复权威稿。
`.rssound` 旧配方仍 v1，新合成结构 v2，读取兼容两版；采样仍用工程携带原件。
当前不是逼真的真实乐器库；多采样、演奏法、FM/波表/任意调制与完整效果链还需推进。

## 4. 最小交流能力

**建议使用明确的能力及输入/输出。** 下列名称是职责描述，不是最终 API 名字，不要求实现一套消息服务器。表中包含目标能力；当前已实现运行中连续更新与第一版完整工程，任意位置跳转和最终后期处理尚未实现，范围以重建进展为准。

| 提供者 | 最小能力 | 结果或通知 |
| --- | --- | --- |
| 公共管理 | 读取内容与依赖、建立编辑稿、查询位置、按路径分离与联合应用、原子保存、复合撤销、完整工程快照与独立导入 | 返回内容身份、使用位置与状态；指出冲突、缺失和不支持的工程版本 |
| 采样获取 | 导入文件、录制、取消、解码、读取采样、保存原件 | 可试听 PCM 与保管后的独立采样；获取失败保留原内容 |
| 旋律识别 | 后台分析单人哼唱、进度/取消、暂存候选、预览、确认采用 | 连续音高与秒时间注释；经音色与乐句公开能力形成可编辑成果 |
| 音色制作 | 创建/修改/检查音色，提供运行所需描述 | 合法的编辑稿内容与执行要求 |
| 乐句谱写 | 创建/修改/检查乐句，提供演奏安排 | 可试听及继续编辑的乐句内容 |
| 歌曲编排 | 放置/移动/删除片段，提供歌曲安排 | 可播放的歌曲范围及连接关系 |
| 引导共创 | 从空白/乐句建立探索、试听并选择方向、接回细调、撤销重做 | 引用可编辑乐句的会话，选中内容由公共管理保管；当前使用离线规则 |
| 声音运行（已确认独立模块） | 建立试听/播放会话，开始、停止、定位和更新；离线生成音频 | 会话身份、实际位置和状态；返回音频或明确失败 |
| 后期处理 | 选择最终处理与输出要求，发起普通音频/完整工程导出 | 可使用的交付文件、进度或失败 |
| 界面渲染 | 呈现状态、接收操作、显示影响和结果 | 将用户意图交给对应公开能力，不直接改内部数据 |

每次请求需要知道作用对象和对应结果。长任务提供进度、取消和失败；过时结果不能覆盖用户已进一步修改的内容。具体线程和传输方式在实现时选定。

同一进程里的普通函数调用，只要遵守共同规范，也可以是正式交流方式；不强制把所有调用序列化成消息。持续音频可以沿规范定义的数据通道流动；不逐点包装成普通命令，也不绕开规范私设含义。

规范由共同上级维护，调用与持续交流由同级自主发生。上级不为每次读取、播放或参数调整审批。

## 5. 一条实际协作示例

用户试听一件音色时：

1. 界面把试听意图交给音色制作的公开能力。
2. 相关执行单位取得音色编辑稿或已保存内容，解析其依赖，形成运行要求。
3. 声音运行建立对应会话，准备所需内容并实际发声。
4. 界面订阅该会话状态；连续修改先编译临时内容，通过公开更新能力让当前试听立即变化，播放位置不从头开始。松手后保管一次编辑，取消或失败恢复已保管内容的计划。
5. 用户停止只结束相关会话；窗口关闭、作品保存与按位置应用分别处理。

当前乐句和歌曲已沿同一交流规范形成完整演奏安排，保留可编辑音符、片段位置和引用，不先混成不可编辑录音。导出时才由声音运行生成普通音频；全过程无需最高指挥中心逐次转发。

## 6. 实现前后的最小验证

- 单音色试听不依赖歌曲模块；没有对话、账号和网络也能完成基础创作。
- 同一首歌内乐句复制只复制相应演奏内容与引用；跨歌曲采用建立独立完整依赖。
- 多个位置引用同一音色：普通修改仅当前路径生效，联合应用只改选中路径，嵌套取消不影响外部作品。
- 保存后的歌曲仍使用派生素材时，撤销当前编辑稿保留其依赖；外部目标已改变时，复合撤销明确拒绝。
- 从同一旧保存状态开启两份编辑稿：先后保存时能识别冲突。
- 播放期间发生编辑：会话能说明使用的内容状态，并能继续更新或明确报告需要重新准备。
- 停止、定位、生成失败与取消不会留下界面和声音互相矛盾的状态。
- 保存重开后，音色、乐句、片段位置及依赖一致。
- 导出普通音频与完整工程分别验证；完整工程在空库离线环境可继续编辑，源库变化不回流。

## 7. 已确认内容与后续留白

**已确认：**采用独立、后台、平行的“声音运行”模块，作为全局实际发声与音频渲染的统一运行边界，按上述主要分工与创作模块协作。记录见 [D-2026-10-22-6](../governance/DECISIONS.md#d-2026-10-22-6--background-sound-runtime-and-global-audio-boundary--active)。

当前声音、乐句和歌曲流程采用明确 Hz/秒的执行计划、拍位置、稳定身份、独立编辑稿和保存修订，并已增加共享发声图的 WAV 输出、素材查询与副本。歌曲默认保留各乐句原速已由用户确认；用户也已明确即时听见修改的重要性，并授权跨重启撤销。同曲复制保留引用、修改默认仅当前处，必要时显式选择联合范围；跨歌曲素材隔离，同类名称唯一。已实现按路径分离、嵌套暂存、原子提交和复合历史。第一版完整工程已通过空库往返、精确播放计划与继续编辑的自动验证；离线共创首版也通过候选选择、细调返回与歌曲采用后的依赖保留验证。这些自动检查不代替界面与听感验收。具体坐标编码、编辑上限、工程容器扩展与更丰富音乐表示仍可调整。

已确定 Windows 桌面软件优先，当前完成可替换的桌面、本地保存与版本目录切换构建；旧窗口保留旧版本，新启动目标不改变用户数据目录。前轮五批及 WAV 已验收，随后实时反馈与持久撤销的实际操作记录保留。按位置编辑一轮曾实测第二片段嵌套音色当前处保存、歌曲保存后撤销重做，以及三个具体位置的嵌套联合应用；父级保存前外部不变，保存后未选位置和原素材保留。后续新增功能的验收范围以进展记录为准。声音运行的最终名称、全部部门、最终音频驱动、最终桌面框架、完整文件容器、多人协作或完整第三方处理器接入均未冻结。
