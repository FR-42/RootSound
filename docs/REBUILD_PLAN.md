## 0. 架构依据与历史范围

- 把本次对话确认的目标、交流规则、公共保管和导出规则写入新架构与治理记录。
- 标明建议和待定项；新项目不自动继承旧目录、数据结构、技术选型或旧待办优先级。
- 用户已要求将旧代码及旧文档集中到子目录，并重新配置 Git。旧原型位于 `legacy/prototype/`，通过自身启动器或 `npm --prefix legacy/prototype run dev` 独立运行。新根入口、检查、测试和构建不再包含旧页面。
- 重建前的 README、架构与路线图文本，以及首次替换首页前的工作文件压缩包，位于[旧历史目录](../legacy/prototype/docs/history/2026-10-22-prototype/INDEX.md)。[工作文件快照说明](../legacy/prototype/docs/history/2026-10-22-prototype/SOURCE_SNAPSHOT.md)列明其校验、排除项和独立恢复步骤；该早期快照不含 Git 历史或浏览器数据。
- 本次旧项目迁移前另存完整工作区与旧 Git 历史档案并核验，再移除活动旧 `.git` 并初始化新历史。`legacy/` 作为本机档案，不纳入新 Git；备份边界和恢复方式见[档案说明](../legacy/README.md)。
- 真正替换或删除代码前，先建立包含未提交及新文件的完整、可恢复旧项目快照；不得仅依赖当前 Git 已提交内容。快照必须能读取，记录排除项和恢复办法。
- 旧项目隔离是已授权的文件整理；未实现的模块与能力仍不能因文档和目录存在而宣称完成。浏览器数据需按原地址另行读取，文件归档不等于搬运浏览器中的创作内容。

验收：已确认原则与设计建议能够区分；旧原型可继续运行；入口文档清楚指出当前状态。

## 1. 新组织方式下的第一条真实创作流程

音频执行归属已确认：采用后台平行的声音运行模块，统一实际发声与音频渲染。动工前继续明确模块公开能力的最小边界、内容引用与编辑稿的最小语义，以及本阶段所需的时间/音高表示。技术选择由这些需求牵引；触及架构原则或用户体验取舍时与用户讨论。

这些边界记录在[第一阶段基础设计](REBUILD_FOUNDATION.md)。声音运行的模块地位与主要分工已经批准；继续将第一条流程必要的数据与交流约定落实成可验证实现，不把其余建议默认为已获批准。

进度：已实现音色制作、公共素材保管、声音运行和界面渲染四个单位的单音色协作。Windows 桌面优先已确认，当前仅用已有浏览器环境验证；乐句、歌曲与最终桌面接入尚未实现。

目标流程：

1. 创建一件能试听的音色，交给公共素材与工程管理保存。
2. 乐句谱写取得这件音色，生成并可修改一段简短乐句。
3. 歌曲编排引用乐句，至少能重复摆放和改变起始位置。
4. 各部分按共同规范协作，保存、关闭、重新打开后继续编辑与试听。

验证要点：

- 模块能自由交流，无需每次经过最高指挥中心批准或转发。
- 音色、演奏内容和歌曲摆放位置分别存在；复制乐句不隐含复制整套音色。
- 公共管理保存内容，执行单位实现音乐行为，界面不直接改兄弟模块内部数据。
- 单个声音能独立试听，不要求建立歌曲。
- 显示和播放响应明确；未实现的部分清楚标注，不用空按钮或假生成冒充功能。

这是一项架构与内容协作验证，尚不代表“零摩擦创作”已经达成。

## 2. 编辑、安全保存与完整导出

- 在两个工程引用同一音色的场景中，验证试调、影响提示、覆盖和另存。
- 覆盖提示能查到未打开但仍有引用的工作工程；另存不会更改原有引用。
- 确定修改冲突和撤销的最小行为，不提前实现多人实时协作。
- 后期处理输出可播放的普通音频。
- 确定完整工程文件的第一版规范，打包所有间接依赖与读取所需信息。
- 在空素材库、断网的兼容 RootSound 环境中重开，能够继续编辑和输出；改变原库不改变已导出的文件。
- 验证目标库里存在同名或相同标识内容时，不发生静默覆盖。

## 3. 面向真实用户的创作入口与精细工具

- 默认欢迎、开始引导、跳过、继续上次，以及自定义启动入口。
- 少步骤进入声音、音色、乐句和歌曲任务；界面不迫使用户学习内部组织。
- 实际验证音符连续拖动、乐句拖拽、直接编辑包络等明确要求。
- 用没有专业经验的用户任务验证：表达成本、试听反馈、纠错和结果可继续修改的程度。
- 视觉与交互需要专门验收，不用“功能存在”替代可用性与品质。

第 1、2 阶段也需要基本可用界面。本阶段表示集中完善完整创作体验，不表示此前可以堆砌粗糙界面。

## 4. 引导共创与 AI 能力

- 实际验证一种输入路径，例如哼唱或参考内容，而非同时建设所有识别方式。
- 旋律底稿与强化方案分别保留，每轮少量候选可试听、选择和返回。
- 选中的方案能交给精细模块，编辑后可回当前会话继续探索。
- AI 接入方法与联网服务按需选择，明确成本、延迟、可编辑输出与离线边界。
- 已取得并保存的完整成果可离线继续编辑。生成失败或等待不打断本地创作。
- 若某算法只能输出混合音频，应如实表达可编辑范围，不称为完整结构化生成。

此阶段与精细模块可交替推进；共创是项目核心体验之一，不能被无限推迟为可有可无的装饰。

## 5. 扩展采样来源与在线生态

按用户实际需求逐项实施：更多采样来源与处理、设备接入、账号、个人创作档案、云保存/同步、创意工坊、发布和交流。

每项都验证：离线基础是否仍可用；内容能否独立搬运；模块是否可替换；使用流程是否增加了不必要步骤。云端和本地同时修改时的处理，在实现同步前专门决定。

多上级关系、复杂插件系统、分布式服务和多人实时协作暂不建设；真正需要时重新讨论。

## 决策节奏

普通内部实现由执行者处理。涉及公共规范、成果含义、不可回退的数据变化、用户交互方式或显著的外部服务依赖时，先提出具体问题与可比较方案，再按确认结果实现。

每阶段都保留可运行、可试听和可恢复的结果。已经确定的原则不反复询问；未决事项在真正影响下一步时再决定。
