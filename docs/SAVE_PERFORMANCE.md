# 保存与退出性能验证

2026-11-26，根项目 `D:\RootSound`。

保存工程的草稿提交、引用整理、校验和序列化移到独立 Worker。后台比较音符内容，未改变的内容只返回引用位置，界面复用原有音符对象及已校验的编辑视图；撤销历史也按位置复用。大型文本分批传入原生服务，批次之间交还主线程，收齐后再统一校验版本并提交。原生草稿提交、正式保存、另存为和退出使用后台任务，完成后查询结果。保存成功不再重绘整份画布，项目切换不再重新加载整个 WebView 页面。鼠标图案在会话切换时保留，覆盖层内的移动也继续更新。

保存前后检查编辑版本和本机会话修订。等待过程中出现新修改时拒绝覆盖当前编辑；写入失败保留修改和原文件。保存完成才清除未保存状态。另存为复用本次已准备的文本，避免再次同步读取整份工程。

## 测量

测试工程含 12,000 个音符。桌面场景对一个音符连续调整力度十次，产生撤销历史，再保存并退出。最终场景每帧移动鼠标，同时核对鼠标图案的位置和对象是否持续保留。使用隐藏的 Electron 渲染窗口加载实际发布入口，连接真实的 Windows NativeStorage、NativeProjectDirectories 和 ProjectDirectoryManager，所有文件位于隔离测试目录。没有操作用户桌面，没有进行实际听音验收。

| 范围 | 修改前 | 修改后 |
| --- | --- | --- |
| Node 工程提交基线 | 主线程连续执行约 287.8 ms，其中 saveDraft 约 216.0 ms | 后台版本的主线程最大事件循环间隔约 18～32 ms；后台任务总用时约 0.6 s |
| 大型工程保存的桌面动画采样 | 最大帧间隔约 1,133 ms；第一轮优化后仍有 50～83 ms | 最终两次连续移动鼠标的场景，最大帧间隔均约 16.8 ms，无超过 50 ms 的长任务 |
| 退出项目的连续鼠标采样 | 首轮仅检查成功退出 | 最终两次最大帧间隔均约 16.8 ms，无超过 50 ms 的长任务 |
| 最终保存与退出鼠标核对 | 原先每次切换销毁并重建图案 | 两次场景分别采样 180 次、171 次移动，位置核对无遗漏，鼠标对象始终保留 |
| 退出项目 | 整页重新加载 | 页面内切换，首次打开到保存退出的页面加载次数保持 1 |

后台处理仍需实际耗时；事件循环间隔和帧间隔不代表保存总时长，也不能据此保证所有硬件和系统负载下零掉帧。

另存为的副本整理已移到后台，取消和原件保护通过验证。但大型副本保存后重新打开，仍沿用工程加载流程；连续移动鼠标的场景测到约 450 ms 的更新间隔。这是当前单独未解决的加载性能问题，不包含在普通保存与退出的约 16.8 ms 结果中。
