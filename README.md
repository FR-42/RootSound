# RootSound

让普通人把想象中的音乐或一段声音，尽快变成能听见、能修改、能继续创作的成果，减少表达想法所需的学习和操作。

**当前是新架构的 Windows 桌面工作站验证版。** 欢迎页“开始创作”直接进入音色制作，主流程为“音色 → 乐句 → 歌曲 → 后期与导出”。音色、乐句和歌曲使用宽幅独立工作区，左侧素材栏可拖入音色或乐句；采样可来自导入、录音，也可把单人哼唱识别为可编辑旋律。歌曲内的首版后期提供总音量、淡入淡出和原声对比，支持 WAV 与携带完整依赖的 `.rsproject` 文件。**灵感共创暂时隐藏并暂停推进**，源码和旧数据保留。AI、偏好学习和完整采样编辑尚未实现。

另有供个人跑通流程的独立 [音乐流程实验](experiments/music-workflow/README.md)，包括手机蓝牙录音、频谱选区采样编辑，以及多段对照的音色打磨。实验不使用主工作站的资料库。

## 一键打开

**日常双击根目录的 `RootSound.exe` 打开桌面窗口。** 这是固定的无控制台入口，直接打开最近一次完整构建的版本，不在启动时下载依赖或编译源码。关闭 RootSound 窗口即可退出，不需要网页服务或外部浏览器。

**`RootSound.bat` 仍然保留，可以一键构建并打开。** 第一次取得源码、修改源码后希望自行构建，或根 EXE 缺失时使用它；首次会获取开发依赖并构建，以后源码没有变化时直接启动。构建同时生成根 `RootSound.exe`，后续日常使用可直接点 EXE。

首次构建需要已安装 Node.js 24、.NET 9 SDK 和 WebView2 Runtime（微软提供的桌面内嵌网页运行组件），本机已具备。构建后的日常使用不需要 Node.js 或 SDK，仍需要 .NET 9 桌面运行环境和 WebView2；根启动器使用本机 Windows .NET Framework。首次获取开发依赖可能需要联网，当前创作、试听、导出与本地保存可离线使用。启动器不会自动安装系统运行环境。

新版本在独立构建目录准备完成后才切换启动目标，不会覆盖正在使用的旧程序。**更新后先关闭使用同一资料库的旧 RootSound 窗口，再双击根 EXE 打开新版。** 同一个资料库只允许一个实例使用。根 EXE 需要配套构建目录和文件，不能只复制这一枚 EXE 到另一台电脑；当前尚非安装包或自包含便携发行版。具体目录与恢复方法见 [Windows 桌面使用说明](docs/WINDOWS_DESKTOP.md)。

手动启动：

```powershell
npm run desktop
```

## 当前可以体验

| 工作区或入口 | 当前功能 |
| --- | --- |
| 采样获取 | 导入音频或录制最长 30 秒的麦克风片段；查看波形、改名、试听、保存采样，并打开已保存采样 |
| 哼唱变旋律 | 30 秒以内的单人清唱或哼唱，本地识别后先试听，确认后直接进入乐句细调 |
| 音色制作 | 明确的新建入口，12 个可编辑起点；最多 4 个声源叠加，五种波形/噪声、独立调音、完整音量曲线、明暗和音高变化；试音键盘、实时反馈、持久撤销；采样可裁切、定原音高与循环延音 |
| 乐句谱写 | 选择已保存声音，点左侧音名或添加音符即可试音；连续拖动与改长短，多声音合奏、框选和多选、成组移动/删除、复制粘贴/重复、力度、缩放、撤销重做 |
| 歌曲编排 | 把已保存乐句拖到时间线，多轨摆放、移动、复制、重复；调整轨道音量、左右位置、静音和单独听，保存与重开 |
| 后期 | 整合在歌曲内：总音量、0–30 秒淡入淡出、原声对比；试听和 WAV 使用同一最终处理，包含自然尾音 |
| 本曲素材栏 | 列出本曲当前音色和乐句，公共起点另列；音色拖入乐句会追加声部，乐句拖入歌曲按落点摆放，双击可编辑 |
| 导出音频 | 从声音、乐句或歌曲导出可直接播放的 WAV；包含自然尾音，显示进度，生成期间可取消 |
| 歌曲工程文件 | “保存工程…”或 Ctrl+S 选择位置，保存当前歌曲、工程成员及其全部依赖；兼容 RootSound 可离线打开继续编辑 |
| 素材管理 | 只列当前歌曲工程的当前实体，按类型搜索、试听、编辑、查看使用关系、另存副本；不列其他歌或历史保存 |
| 启动设置 | 关闭欢迎页，指定启动工作区或使用上次工作区；欢迎页“继续创作”仍回到上次使用的位置 |

共创入口已从欢迎页、导航、素材分类和启动设置中隐藏；旧共创启动位置回到音色制作。当前优先完善手动创作。素材栏跟随正在编辑的作品归属，避免显示其他歌曲里不能直接使用的素材；独立音色或乐句显示公共素材。已有歌曲时，顶部进入乐句会优先接回本曲已有内容，未完成的公共稿仍保留。

顶部“采样获取”提供“导入音频…”和“录一段”。导入保留原文件字节，能否解码取决于格式和运行环境；麦克风录音需要正常授权，当前保存为单声道浮点 WAV。暂定单文件 16 MiB、解码后 120 秒和 64 MiB，系统播放声音的直接录制仍未实现。

完成获取后可点 **“用这段声音制作音色”**，保存原采样并进入独立工作区。选择播放范围、原音高并试听；“延长声音”里可启用循环，保留声音开头并重复指定片段直到音符收音。参数单独保存，原文件保留。当前移调仍同时变速，尚无保持时长移调、多采样键位/力度映射或自动寻找平滑循环点。

采样点“保存采样”后才进入资料库。未保存内容只在内存中，切换工作区会保留本次已完成的采样，但完全退出软件会丢失。导入、录音或打开另一采样前，如有未保存修改，会提供“保存后继续 / 放弃并继续 / 返回”；取消、获取失败或保存失败保留原采样，可继续重试。离开工作区会停止并取消未完成录音。

单人清唱或哼唱可点 **“把哼唱变成旋律”**，再点“听听识别结果”。喜欢后选“去细调”才保存乐句，不必先保存原采样；想保留原录音，仍需另点“保存采样”。它按演唱时间整理音符与休止，不猜歌曲速度或调性，也不自动纠音。超过 30 秒会拒绝，不自动截断；带伴奏、多人演唱和滑音等内容可能不准确，需试听核对。当前不是 AI 或人声分离，尚未经过真实人声和界面体验验收。

也可直接使用精细工作区：先保存一个声音，写一段乐句并保存，再进入“歌曲编排”拖入乐句。声音或乐句可独立试听、保存和导出，不必先建立歌曲。

歌曲默认**各乐句保留原速**，这是用户已确认的规则；也可在歌曲中明确改成“跟随歌曲速度”。例如原速 90 拍/分钟的乐句放入 120 拍/分钟的歌曲，默认仍以 90 演奏，切换规则后才按 120 演奏。修改规则不会改写源乐句的音符。

乐句编辑可拖空白区域框选，用 Ctrl 或 Shift 点选增减选择；复制、粘贴、重复、删除和方向键移动均作用于选中音符。复制默认把粘贴位置放在所选音符之后；Ctrl 点空白可另选粘贴位置。音符拖动连续显示，松手才提交一次修改；取消拖动不改内容。水平移动与缩放不会强迫原音高落入键盘格。

钢琴卷帘使用一个连续窗口，上下滚动可查看全部可用音高，无需切换音区。当前键盘包含 E0–D♯8 的 96 个音高；20–5000 Hz 的自定义音高也会显示并保留原频率。初次打开对准旋律主要位置，空稿对准 C4，同稿调整保留滚动位置。

当前乐句是多种声音一起演奏的一段音乐：亮色音符属于当前选中的声音，淡色音符属于其他声音，仍会播放；点击淡色音符可切换编辑。左侧音名使用当前声音试音，新添音符在成功保存该次修改后试音；采样音色首次需要准备。短试音不会重启正在播放的乐句。此轮保留淡色显示规则，整体呈现与创作导航仍需后续细查。

播放时调整声音、乐句或歌曲会沿当前进度实时反馈，拖动途中即可试听变化；松手才保存一次修改，取消或保存失败会恢复临时试听。更换作品或切换工作区仍结束当前试听。乐句和歌曲的撤销重做随各编辑稿保存，关闭重开后可继续使用，每稿当前最多 64 步；升级前没有记录的操作不能追溯恢复。普通撤销只改编辑稿，联合应用可整体撤回当次选中的位置；之后另行保存的作品不随编辑稿撤销回退。

## 保存、引用与文件

**桌面数据保存在 `%LOCALAPPDATA%\RootSound\materials.json`。** 已保存声音、采样、乐句、歌曲及独立编辑稿都在其中；相邻的 `materials.json.bak` 保留上一次写入前的版本。原始采样当前没有持久编辑稿，未保存的采样不在此文件中；已确认的识别乐句另行保存。写入失败明确报错，原数据保留，不伪报保存成功；损坏库不会被当作空库清除。

本机编辑稿持续保留，用于关闭后恢复；它与选择位置写出的工程文件分别保存。**素材管理只显示当前歌曲工程**：同一实体的已保存状态与有效编辑稿只列一次，优先展示当前编辑状态；只为旧保存或撤销恢复保管的内容不列为当前素材。公共起点只在实体栏的“素材库”另列。没有当前歌曲时，素材管理为空，不混入独立音色和乐句。

乐句引用音色，歌曲引用乐句。**一个使用位置引用时，普通保存覆盖原实体；多个位置引用时，为当前这一处新建实体。** 双击歌曲片段进入乐句，再调整音色，沿途必要的乐句也按同一规则判断。同一位置的已保存状态和编辑稿合算一次，临时细调稿不增加引用；普通稿新添的引用仍受保护。库内直接打开实体，零或单引用可覆盖，多引用另存副本；明确“另存”始终创建新身份。

**不同歌曲的素材彼此隔离。** 从公共起点为歌曲选用素材时，会带入本曲独立的乐句、音色及原采样；同一首歌重复采用未变的同一来源，会复用本曲已有素材。另存新歌曲、从共创建立歌曲或打开工程，也会保留独立身份。公共素材仍统一保管，但修改一首歌的素材不会改到另一首。

**同一首歌、同一种类的不同素材不能重名。** 音色“雨”和乐句“雨”可以并存；同一音色被多个乐句引用也没有问题。另一首歌可以使用同样名称。手工改成重名会提示并保留修改，自动生成副本时会补充数字；从排列移除但仍保留在本曲的素材也保留其名称。旧库不会在打开时批量改写，编辑相关歌曲时才逐步隔离；旧历史撤销仍可能恢复当时的共享状态，再次编辑会重新隔离。

尚未交给歌曲的公共素材也按种类避免重名；这补上了先前只约束歌曲内部的遗漏。手工重名会要求换名，新建、派生或导入默认补数字，不同歌曲可以同名的规则不变。工作稿与它对应的已保存实体是同一份内容的两个状态，不当作两个重名音色。

音色制作的 **“新建音色”** 在细调状态下也可使用。可从纯净声音、琴键、拨弦、铃声、主音、低音、铺底、鼓和风声等 12 个电子起点开始，也可走采样路线。每个电子起点都可编辑声源、音高、音量的起音/回落/保持/收音、明暗和音高回落；音高微调及额外变化按需展开。旧三套配方保持原声，只在实际编辑时转换。当前没有逼真的钢琴、吉他等真实乐器素材库，电子起点不等于真实乐器仿真。

音色制作只突出一个“保存”；“另存副本”和“应用到其他位置…”收在旁边的“⋯”中，有相应操作时才显示。从当前使用位置进入编辑时不提供绕过该位置的另存。乐句页面也可选择“应用到其他位置…”，或右键片段、声音选择“联合修改…”，再按作品和位置选范围。从乐句内调整声音时，选中的其他位置等到保存这段乐句才一起生效；取消不提前改动它们。一次联合应用可一步撤销、重做，相关作品后来另有修改时会提示冲突。

同一首歌内复制片段仍只复制引用，不展开整套依赖；素材管理中的声音或乐句“另存副本”也保留本曲下层引用。跨歌曲采用和另存新歌曲则建立独立依赖。嵌套细调先暂存，外层保存才覆盖或分离，取消不提前影响原实体。覆盖之后若又保存或修改了上游歌曲，旧事务撤销会拒绝影响这个后来保存的版本；普通未冲突的撤销重做仍支持跨重启恢复。

| 文件 | 用途与范围 |
| --- | --- |
| `.rssound` | 单个无外部依赖的电子音色，含当前名称和全部参数；旧配方使用 v1，新合成结构使用 v2，当前均可读取；采样原件仍随 `.rsproject` 携带 |
| `.wav` | 可在其他播放器直接播放的无损音频；当前界面输出 48 kHz、24 位、双声道，不含可编辑音符和引用 |
| `.rsproject` | 当前歌曲稿、显式工程成员及其依赖，含乐句、音色全部参数与原始采样；可继续编辑，不是可播放音频或整库备份 |

在歌曲编排点 **“保存工程…”** 或按 **Ctrl+S**，都会打开位置选择，写出 `.rsproject`；空歌曲也可以保存。欢迎页或歌曲工具栏的 **“打开工程…”** 可读入文件。保存捕获点击时的当前工程，不要求先存一份内部歌曲；还有这首歌的乐句或声音正在细调时，须先完成或取消。后续修改仍需再次保存工程文件，本机自动恢复不表示文件已更新。

打开工程会一次导入独立的新歌曲、乐句、音色和采样身份，保留包内共享关系，不覆盖同名作品；原先的编辑稿仍保留。在素材管理中明确另存的副本属于本曲成员，即使尚未放进编排也随文件保存。没有附加成员时继续使用 v1；有显式成员时使用 v2，当前可读取两版。文件严格收齐歌曲与成员的依赖，拒绝缺失、循环或无关孤立内容；不携带其他歌曲、旧保存、撤销记录、编辑上下文或本机偏好。原始采样只携带一份，不依赖原电脑路径；压缩格式仍需要目标环境能解码。暂定上限为 32 MiB、8192 份内容。

Windows 原生对话框成功写入后才提示文件已保存；取消或写入失败不报成功，并保留当前创作。浏览器验证版只能报告“已发起下载”，文件是否完成需在浏览器中确认。

此前浏览器作品不会自动搬到桌面。可在原地址与端口打开浏览器验证版，通过工程文件搬运整首歌曲及所用素材，或逐个导出、打开声音文件。当前没有独立乐句交换文件或整库迁移功能。

## 开发与验证

建议使用 Node.js 24 或更新版本；测试使用 Node.js 直接执行 TypeScript。

| 命令 | 作用 |
| --- | --- |
| `npm run desktop` | 必要时构建并启动 Windows 桌面窗口 |
| `npm run desktop:build` | 构建新版本，完整成功后切换桌面启动目标 |
| `npm run dev` | 可选浏览器开发验证服务 |
| `npm run check` | 检查新项目类型 |
| `npm run test:workstation` | 验证声音、乐句、歌曲、素材、设置、保存、导出、平台接入与模块边界 |
| `npm run test:launcher` | 隔离验证根 EXE 的版本选择、路径约束和参数传递，不打开真实界面 |
| `npm run test:desktop-entry` | 用隔离文件验证入口首次发布、重复构建、更新和失败保留，不启动程序 |
| `npm run build` | 构建新界面到 `dist/` |

新源码位于 `src/workstation/`，由公共规范、应用装配和独立模块组成。根 EXE 与开发启动脚本读取 `.cache/desktop-build.current`，选中 `.cache/desktop-builds/<构建编号>/` 中的程序；旧 `desktop/RootSound.Desktop/bin/Release/` 路径不代表当前选中的版本。根 EXE 是可重新生成的产物，不进入源码 Git；新检出源码先用 BAT 或构建命令生成。

本轮音色强化：**483 项应用检查全部通过**，新增 17 项，类型检查与完整 Windows 构建通过，0 警告、0 错误，详情见[重建进展](docs/REBUILD_PROGRESS.md)。原生宿主与启动器未改，历史文件检查未重复计数。只使用源码和隔离的程序化检查，不观察屏幕、不操控桌面、不访问真实资料库或设备。实际显示与听感仍待验收，“零摩擦创作”仍是持续验证的目标。

## 旧项目档案

旧原型的代码、样式、测试、文档与原治理记录已集中到 [`legacy/prototype/`](legacy/prototype/)，作为独立旧项目保存。根入口不导入、构建或显示旧页面。比较旧实现时，可双击该目录自己的 `RootSound.bat`，或运行：

```powershell
npm --prefix legacy/prototype install
npm --prefix legacy/prototype run dev
```

旧原型使用独立的 `http://localhost:5174/`，新旧数据不自动转换。浏览器数据按地址和端口保存，移动文件不会搬运这些数据。

此前的[旧工作文件快照](legacy/prototype/docs/history/2026-10-22-prototype/SOURCE_SNAPSHOT.md)保留；迁移前工作区与旧 Git 历史另有 `legacy/` 内的压缩备份。活动 Git 已重新初始化，新历史仅跟踪新项目；`legacy/` 留作本机档案，不纳入新 Git。恢复说明见 [`legacy/README.md`](legacy/README.md)。
