                              subtract_inplace=False)

                           sample_rate=..., hop=..., write_pcm=None)

Each request preserves channel/candidate identity, fit_begin/end, the separate
energy_begin/end, native frame_index and candidate frequency. The request owner
must derive those fields from the recovered candidate workflow; this boundary
does not pick an FFT-sized or whole-file replacement window.

The first interface borrows in-memory PCM. The second owns one requested block
while retaining absolute sample coordinates. Its optional write callback commits
only the native kernel's written range. Both execute the same raw, constant-
frequency estimator. Each result retains four phase statistics and three native
objective coefficients, in addition to amplitude/phase/improvement and all bounds.

Operation boundary:
- Native raw signed-int16-scale PCM is represented as float32; no implicit gain
  conversion or normalization is applied here.
- Inputs need an identified candidate frequency; this is not a pitch detector.
- Chirp, preweighted and filtered-band branches explicitly remain unsupported.
- Optional immediate subtraction uses reconstructed3190b0 at raw estimated
  amplitude. This does not stand in for31c500's full trajectory-strength mapping,
  filter responses, quantization, channel averages or candidate scheduling.
- Intermediate records are not final notes or MIDI events.
- No public AI model, FFT, generic least-squares replacement or guessed threshold
  is introduced in this connection.
